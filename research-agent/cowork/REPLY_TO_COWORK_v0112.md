## 2. 그쪽이 확인해 주실 것 — 제가 **제안서 스키마에 맞춰 짰습니다**

실물 payload 를 아직 못 봤습니다. 아래 필드를 키로 씁니다:

```
week.end → week.start → created_at[:10]   중 처음으로 YYYY-MM-DD 인 것이 파일명
items[].source                            jsonl 중복 제거 키 (없으면 notion_url → headline|date)
items[].scooping / scooping_why           노트 맨 위 경보 callout
items[].headline / date / summary / body_markdown / axes / notion_url
```

덮어쓰며 여러 주가 한 파일에 뭉개져서요. 거부해도 메일은 안 본 것으로 남아 다시 걷힙니다.

## 4. 시험 20건 + 뮤테이션

첫 메일이 9/11 에나 오는 코드라 "되면 이렇게 된다"는 실물이 알려 줍니다.
지금 잠근 것은 **조용히 망가지는 쪽**입니다:

```
논문 payload 를 뉴스로 안 받는다 (반대 방향도 막아야 대칭이 성립합니다)
날짜 못 읽으면 News/None.md 를 안 만든다
축소 덮어쓰기 거부 · source 없는 항목을 안 버린다
우리가 wikilink 를 안 만든다 · 헤드라인의 `:`·따옴표가 frontmatter 를 안 깬다
뉴스가 논문 DB 로 안 샌다 · 두 태그가 실제로 다르다
```

보호 5개를 하나씩 빼 봤고 **해당 시험이 전부 죽습니다.** 92 passed (+20).

> ⚠ 픽스처 교훈 하나 — 처음엔 `message_from_string` 으로 메일을 만들었는데 한글 첨부가
> 통째로 안 읽혔습니다. str 메시지는 `get_payload(decode=True)` 가 raw-unicode-escape 로
> 인코딩해 UTF-8 이 깨지기 때문인데, **실물 경로는 `message_from_bytes` + base64** 라
> 그런 일이 없습니다. 즉 코드가 아니라 **픽스처의 결함**이었습니다.
> 픽스처가 실물보다 험하면 없는 버그를 쫓게 됩니다 — bytes 왕복으로 고쳤습니다.

handoff·news 가 같은 함수를 씁니다. 두 벌이면 한쪽만 고쳐지는 순간(dedupe·lookback·인코딩)
