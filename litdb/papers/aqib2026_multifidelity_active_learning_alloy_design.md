## 0. 이 digest 를 읽는 법 — 3줄 경고

1. **이 논문에는 우리 계(황화물 argyrodite)의 물성값이 0개다.** Fe–Ni–Co–Cr–V–Cu 합금의 열팽창계수(CTE)뿐이다. ⛔ **물성 4축(A 이온전도 / B 산화안정 / C 기계 / D 전자구조) 어디에도 수치를 넣지 않는다.** 쓰는 곳은 **파이프라인 구조 축(J) 하나**다.
2. **이 논문에는 계산(DFT/MD)도 실험도 없다.** "high fidelity" 는 **Rao 2022 데이터셋의 라벨을 그냥 읽는 것**이고, "low fidelity" 는 **그 라벨 30% 로 학습한 GPR 의 예측**이다. 즉 **두 층이 같은 원천에서 나온다** — 뒤에서 자세히(§12.1).
3. **본문 · SI · 공개 코드가 서로 안 맞는 곳이 최소 7군데다** (§10.2 표). 우리가 이 편에서 가져갈 것은 **숫자가 아니라 구조적 교훈**이다.

## 1. 한 줄 요약

Rao 2022 *Science* 의 **717 조성 Fe-Ni-Co-Cr-V-Cu 합금 데이터셋**에서 **CTE 최소 조성**을 찾는 이산 최적화 문제를, **Multi-Task GP(2-fidelity ICM) + 비용가중 EI/KG/LCB 혼합 획득함수**로 푼다. 세 방법(GPR-EI · GPR-LCB · MFAL)이 전부 **동일한 Invar 조성(≈63.5% Fe, 30.5–32.5% Ni, 4–6% Co)** 과 **동일한 CTE 0.1 ×10⁻⁶ K⁻¹** 에 도달하고, MFAL 은 **고정확도 평가 비율을 55–65%(비용비 1:5) / 43.6%(1:20)** 로 줄인다. — **단, 그 "감소"의 대부분은 알고리즘이 학습한 것이 아니라 코드에 손으로 박은 확률 스케줄이다**(§10.1).

## 4. DFT/계산 방법 ★

**없다. 이것이 이 논문의 가장 중요한 사실이다.**

- **code / version**: DFT 코드 없음. **PyTorch + BoTorch + GPyTorch + scikit-learn + XGBoost + pycma**
- **functional / pseudo / k-points / ecut / supercell / nat**: **해당 없음** (원자단위 계산 0회)
- **DFT+U**: 해당 없음
- **AIMD / MD**: 해당 없음
- **MLIP**: 해당 없음
- **무질서 처리**: 해당 없음 (조성이 **연속 설계변수**로만 존재하고, 어떤 구조도 만들지 않는다 — SQS·enumeration 개념 자체가 등장하지 않는다)
- **CALPHAD**: 서론에서 **언급만** 하고 쓰지 않는다
- ⇒ 논문이 §3.4.4 에서 *"low-fidelity 는 CALPHAD 나 고속 DFT 에 대응하고 high-fidelity 는 정밀 dilatometry 에 대응한다"* 고 쓰는 것은 **비유이지 실행이 아니다.** 실제로 돌린 것은 **데이터셋 라벨 읽기(HF)** 와 **그 라벨로 학습한 GPR 예측(LF)** 두 개뿐이다.

### 4.1 실제로 쓴 알고리즘 스택

| 요소 | 구현 |
|---|---|
| 전처리 | Pandas `isnull` → 결측 0 · zero-variance 0 · **StandardScaler** · 이상치 3종(**LOF** k=15 contamination 0.05 / **IsolationForest** / **One-Class SVM** ν=0.05, RBF) — **이상치 제거는 ML 학습셋에만 적용, AL/MFAL 풀에는 미적용** |
| 차원축소 | PCC → **VIF**(임계 10) → **RFE**(RF 기반) → **PCA 5성분** (설명분산 99.9957%, 재구성 MAE < 10⁻⁶, VIF = 1.0 보장) |
| 단일정확도 대리모델 | **BoTorch `SingleTaskGP`** (RBF+ARD, `ExactMarginalLogLikelihood`) / **RFV** (RandomForest + 앙상블 분산) |
| 획득함수 | **EI** (식 7) · **LCB** (식 8, 적응형 β 식 9–10: `β(t)=max(0.5, 3.0(1−t/n_iter))`) · **KG** (식 11–12) |
| 다중정확도 대리모델 | **BoTorch `MultiTaskGP`** — `k((x,t),(x',t')) = k_base(x,x') × B_{t,t'}`, **B ∈ ℝ^{2×2}** (ICM) |
| 다중정확도 획득함수 | **α = w_EI·EI + w_KG·KG + w_LCB·LCB** (식 17), HF 에 **α/C_adaptive**, `C_adaptive = C_base(0.5 + 0.5·progress)` (식 18–19) |
| 대조군 | **CMA-ES** (pycma), 연속 제안을 유클리드 최근접 실제 데이터점으로 사상(식 S5), 100런 × 200 iter |
| 미보고 대조군 | **random search** — `Fig. S6` 로만 존재, 본문에서 **한 번도 인용되지 않음** (§10.3) |

| 지표 | 정의 (SI 식) | 이 논문의 값 |
|---|---|---|
| **Simple regret** | `R_t = f(x_best,t) − f(x*)` (S6) | §3.3 표 |
| **Cumulative regret** | `CR_T = Σ_t R_t` (S7) | GPR-LCB 81.38 (최저) |
| **Spatial diversity** | 선택점들의 평균 쌍거리 (S8) | 값 미보고 |
| **Convergence speed T_p** | `min t : f(x_best,t) ≤ (1+p)·f(x*)`, p = 10%/5%/1% (S9) | `Table S10` 은 λ 와 "99% gap" 만 |
| **Half-life λ** | 지수적합 수렴률 | GPR-LCB 0.118 (최고) |

### 7.4 ★ 불확실도 보정 — 이 논문에서 가장 정직한 한 단락 (§3.2.3 말미, `Fig. S8`)

저자 해명: *"AL 은 절대오차 예측이 아니라 후보 순위매기기에 불확실도를 쓴다. 엄밀한 확률적 보정이 아니라 **효과적인 불확실도 순서**만 있으면 충분하다."*

## 8. 논증 흐름 (저자의 주장 구조)

1. HEA 설계공간은 크고 CALPHAD/DFT 는 비싸다 → 데이터 기반이 필요하다.
2. 그러나 ML 도 큰 학습셋이 필요하다 → **능동학습**으로 표본수를 줄인다.
3. AL 이 진화알고리즘(CMA-ES)보다 **일관되다** (CV 8.34% vs 62.88%).
4. AL 도 매 반복 비싼 평가를 요구한다 → **다중정확도**로 비싼 평가 비율을 줄인다.
5. MTGP + 비용가중 획득함수 + 4단계 가중치 스케줄 → **HF 55–65%(1:5) / 43.6%(1:20)** 로 동등 품질.
6. 세 방법이 **같은 Invar 조성**에 수렴 ⇒ 물리적으로 타당 ⇒ 프레임워크 신뢰.

**약한 고리는 4→5 다.** 5의 "감소"가 **알고리즘의 결정인지 스케줄인지**를 논문은 분리하지 않는다. 코드는 스케줄이라고 답한다(§10.1).

```python
if progress > 0.9:  high_fid_threshold += 0.15
if torch.rand(1).item() < high_fid_threshold:
    selected_fidelity = 1 ...
else:
    selected_fidelity = 0 ...
```

즉 **① 층을 손으로 정한 확률 스케줄로 뽑고 ② 그 층 안에서만 최선 후보를 고른다.** 획득함수는 *어느 점* 을 고르는 데만 쓰이고, *어느 층* 인지는 **거의 난수**다(예외는 두 개: `best_high_value > best_low_value*0.95` 이고 improvement_ratio<1.2 이면 LF 로 폴백; progress>0.5 이고 HF 획득값이 2배 이상 좋으면 HF 로 override).

**세 가지가 이 해석과 정확히 맞는다.**
1. **`Fig. S15` 의 평균 HF 비율 ≈0.60** = `E[0.7−0.4·progress] = 0.5` + 초기/말기 부스트. **논문이 "결과"로 보고하는 55–65% 는 사실 "입력"이다.**
2. **본문의 "이론 전략 vs 관측 전략 상관 0.0874"** — 저자는 이것을 *"적응형 비용 기전의 효율을 확인"* 이라고 읽는데, **무상관은 확인이 아니라 부인**이다. 획득함수가 처방한 층과 실제로 고른 층이 무관하다는 뜻이고, 그게 바로 동전던지기다.
3. **`Fig. 7` 에서 iteration 67–71·92 에 CTE 9–14 의 저정확도 점**이 찍힌다(figure-read). 후반부에 명백히 나쁜 조성을 계속 뽑는 것은 "탐색 전략" 이 아니라 스케줄이 강제한 LF 슬롯을 채우는 행동으로 보는 게 자연스럽다.

⇒ **★3(획득함수와 층 선택을 동시에 정하는가)의 답: 논문은 "그렇다" 고 쓰지만 코드는 "아니다" 다.**

### 10.4 🔴 "theoretical minimum" 은 이론값이 아니다

### 10.5 🟠 "동등한 해 품질" 이 정량화되지 않았다

- 논문은 단일정확도 4조합에 대해서는 **최종 simple regret · 표준편차 · 누적 regret 를 전부 표로** 준다(`Table S13`).
- **MFAL 에 대해서는 그 어느 것도 주지 않는다.** *"comparable solution quality"* 라는 서술뿐이다.
- 그런데 **`Fig. 6` 의 평균 곡선은 ≈0.3–0.35 에서 끊긴다**(figure-read) — 단일정확도 GPR-LCB 의 평균 최종 best 인 **0.105**(= 0.1 + regret 0.0052)와 **3배 차이**다. 두 그림이 같은 조건이라고 단정할 수는 없지만(`Fig. 6` 은 1:5, 런 길이가 제각각), **그 차이를 해소하는 숫자를 논문이 제시하지 않는다는 것이 문제다.**
- `Fig. 8`(1:20)은 200 iter 를 끝까지 돌아 둘 다 0.1 부근에 온다. 그러나 figure-read 로 **iter 10–75 구간에서 단일정확도가 계속 앞선다** — 캡션의 *"nearly identical trajectories"* 는 그림과 어긋난다.

### 10.6 🟠 다중정확도가 **원리적으로 이득이 없는 설정**이다 (저자 자신의 숫자로)

§3.4.2 의 두 숫자:
> 개선/단위비용 = **HF 0.007508**, **LF 0.007103**, 비율 **1.06**

두 층이 **단위 비용당 거의 똑같은 개선**을 준다는 뜻이다. 그러면 **주어진 예산에서 어떤 혼합비를 쓰든 결과가 같다** — 다중정확도가 이득을 낼 여지가 구조적으로 없다. (이득은 "싼 층이 비용 대비 더 효율적인 구간" 이 있을 때 생긴다.)
저자는 이것을 *"두 층의 시너지"* 로 읽지만, **1.06 은 시너지가 아니라 무차별(indifference)** 이다.
⇒ 그렇다면 §3.4.3 의 "비용 절감" 은 무엇인가? **평가 횟수를 세는 방식의 문제**다 — 다음 항.

### 10.7 🟠 "56.4% 비용 절감" 의 산술 — **저정확도를 공짜로 셌다**

- `Fig. 8`: MFAL HF **43.6%**, 단일정확도 HF 100%. 주장 절감 **56.4%**.
- **56.4 = 100 − 43.6 이다.** 즉 **저정확도 평가의 비용을 0 으로 놓은 계산**이다.
- 비용비 1:20 을 실제로 적용하면: MFAL 평가당 평균비용 = 0.436×20 + 0.564×1 = **9.284** vs 단일정확도 20 ⇒ **53.6% 절감**.
- 숫자 차이는 작다(56.4 → 53.6). **문제는 회계 방식이 드러난다는 것**이다. 1:5 에서 같은 방식을 쓰면 훨씬 크게 어긋난다(HF 60% ⇒ 평가당 3.4 vs 5 = **32% 절감**인데, "40% fewer HF evaluations" 로 서술된다).
- ⇒ **★4(이득의 분해)의 답**: 논문은 분해하지 않는다. 우리가 분해하면 — **"MF 구조 덕" 은 0 에 가깝고(§10.6), 절감은 전부 "싼 층을 스케줄로 많이 쓴 것"(§10.1)** 이다. Ou 2026 의 5.4× 중 획득 자체는 1.8× 였던 선례보다 **더 극단적**이다: 여기서는 획득함수 몫이 **사실상 0** 이다.

### 10.8 🟠 거짓 음성(false negative) 감사가 **없다** — 그리고 있을 수도 없다

- **★5 의 답: 하지 않았다.** 단어("false negative")조차 나오지 않는다.
- 구조적 이유: **아무것도 탈락시키지 않기 때문이다.** 저정확도 평가는 후보를 버리는 데 쓰이지 않고, 단지 MTGP 학습셋에 (예측값 라벨로) 들어갈 뿐이다. 문턱도 게이트도 없다.
- ⇒ **Basu 2026 과 정확히 같은 구조적 결함이다** — 이름은 다르지만(그쪽은 "funnel", 여기는 "multi-fidelity") **둘 다 선별(selection)이 아니라 재채점/보강(augmentation)** 이다. §12.5.
- **그런데 `Fig. S7` 이 이 문제의 심각성을 보여준다**: 저정확도 GPR 은 **예측값이 ≈2.2 아래로 거의 내려가지 않는다**(figure-read). 목표는 0.1 이다. **만약 이 층을 게이트로 썼다면 진짜 최적을 확실히 버렸을 것이다.** 논문이 이 위험을 피한 것은 설계가 좋아서가 아니라 **게이트를 안 만들었기 때문**이다.

### 10.9 🟠 벤치마크가 너무 쉽다

- 설계공간 = **717 조성(음수 제외 후 ~700)** 의 **이산 유한집합**. `Fig. S6` 이 보여주듯 **무작위 추출도 432회면 최적을 찾는다** — 공간의 **62%** 를 뒤진 셈이다.
- 200 iteration 은 공간의 **~29%** 다. 이 정도 예산에서는 "찾는다"가 놀랍지 않다.
- **CMA-ES 도 GPR-EI 도 GPR-LCB 도 100% 성공률**이다. 차이는 소수 실패런이 만드는 평균의 꼬리뿐이고, `Fig. 5` 에서 세 방법 모두 **25 백분위가 regret 10⁻⁷ 아래**로 떨어진다(figure-read).
- **최종 CTE 차이 0.105 vs 0.12 ×10⁻⁶ K⁻¹ 는 어떤 dilatometry 로도 구별되지 않는다.** "우수성" 이 물리적으로 무의미한 자릿수에서 논해진다.

### 10.10 🟠 층 간 상관을 **보고하지 않는다**

- MTGP 의 본체는 **B ∈ ℝ^{2×2}** (층 간 상관행렬)다. 식 (16) 에 정의만 있고, **학습된 값이 논문 어디에도 없다.**
- 층 간 신뢰도의 조성 의존(§3.4.4, "Fe-rich 에서 상관이 높다")은 **수치·그림·코드 근거가 전혀 없는 서술**이다.
- ⇒ **★2 의 답: 상관 모형은 ICM(분리형 MTGP) 이고, 저정확도가 고정확도를 잘못 인도하는 경우를 탐지하는 장치는 없다.** `Fig. S7` 의 잔차 구조(저CTE 구간 체계적 과대예측)는 논문이 언급조차 하지 않는다.

### 10.11 🟠 저정확도 층이 **독립 정보원이 아니다** (fidelity leakage)

`MFAL.py:62-82`:
```python
X_tr, X_te, y_tr, y_te = train_test_split(X_tensor, y_tensor, test_size=0.7, random_state=42)
middle_fidelity_model = SingleTaskGP(X_tr, y_tr); fit_gpytorch_mll(mll)
...
y_low = middle_fidelity_model.posterior(X_tensor).mean   # 전 설계공간의 LF 라벨
y_mogp = torch.cat([y_low, y_tensor], dim=0)
```
- 저정확도 "실험"은 **고정확도 라벨 30% 로 학습한 GP 의 사후평균**이다.
- ⇒ 두 층의 상관은 **설계상 보장된다.** 실제 다중정확도 문제(예: UMA vs DFT)에서 가장 위험한 것 — **싼 층의 계통오차가 비싼 층과 상관되지 않는 경우** — 이 이 벤치마크에는 **원리적으로 존재할 수 없다.**
- 그리고 `Fig. S7` 의 R² = 0.5526 도 **같은 데이터의 70% 홀드아웃 성능**이지, 다른 물리로 잰 값의 상관이 아니다.
- ⇒ **★1 의 마지막 질문("층 정의에 근거가 있나, 아니면 있는 데이터가 그래서인가")의 답: 후자다.** 그것도 강한 의미로 — **층이 데이터에서 유도된 게 아니라, 하나의 데이터에서 인위적으로 만들어졌다.**

### 10.12 ⚪ 사소하지만 기록해 둘 것
- `MFAL.py:330` — 예산 임계(<5%)에서 `torch.argmax(mean[:,0] − sqrt(var[:,0]))`. **최소화 문제인데 argmax** 다. 방향 버그로 보인다(같은 파일 336줄은 `argmin` 으로 올바르다). 예산이 720 이라 이 가지는 거의 안 타는 듯하지만, 타면 **가장 나쁜 후보를 고른다**.
- `AL_GPR.py:418` — `niter = 500`. 본문/SI 는 200 iter 로 서술. repo 에 `AL_GPR_100runs`(200) 와 `AL_GPR_100_500runs`(500) 두 pkl 이 있다.

### 10.13 ⛔ 인용 금지 목록

- ⛔ **어떤 CTE 값도 우리 문서에 옮기지 않는다.** 우리 계와 무관하고 단위·온도 정의가 불명확하다.
- ⛔ **"이론적 최소 CTE" 표현 금지** — 필터링된 데이터셋 최솟값이다(§10.4).
- ⛔ **"55–65% HF 로 동등 성능" 을 우리 캐스케이드 예산 근거로 인용 금지** — 그 비율은 결과가 아니라 **코드에 박힌 스케줄**이다(§10.1).
- ⛔ **"56.4% 비용 절감" 인용 금지** — 저정확도를 공짜로 센 회계다(§10.7).
- ⛔ **"5× 속도 향상" 인용 금지** — 산출 근거가 논문에 없고, 대조군 그림(`Fig. S6`)이 본문에서 인용조차 안 된다(§10.3).
- ⛔ **"MFAL 이 단일정확도와 동등한 해 품질" 인용 금지** — MFAL 의 최종 regret·표준편차가 **보고되지 않았다**(§10.5).
- ⛔ **ML 모델 R²/RMSE 5종 인용 금지** — preprint 와 게재본 사이에서 값이 뒤바뀐다(§2.2).
- ⚠ **식 (17) 을 그대로 옮겨 쓰지 말 것** — 최소화 문제에서 LCB 항의 부호가 틀렸다(코드가 옳다).
- ⚠ **"RBF 커널" 로 인용하지 말 것** — MFAL 코드는 Matérn 5/2 다.

## 12. ★ 우리 cascade 재설계에 주는 것

> ★1–★8 의 답을 여기 모은다. **근거 없는 일반론은 넣지 않았다.** 논문에 없는 것은 "논문에 없다" 로 적었다.

### 12.1 ★1 — fidelity 를 몇 층으로, 무엇으로 잡았나

| | **저정확도 (t=0)** | **고정확도 (t=1)** |
|---|---|---|
| 이름 | "low fidelity" | "high fidelity" / "ground truth" |
| **실체** | **`SingleTaskGP` 를 데이터셋의 30% 로 학습해 얻은 사후평균** (`MFAL.py:62-77`) | **Rao 2022 데이터셋의 CTE 라벨을 읽는 것** |
| **정확도** | **R² 0.5526 · RMSE 2.877 · MAE 2.0105** (`Fig. S7`) | 정의상 완전 (오차 0) |
| **비용** | **1 unit (명목)** | **5 unit (기본) / 20 unit (robustness 실험)** |
| **비용의 근거** | ⛔ **없다.** *"계산이나 실험에서 흔한 자원 trade-off"* 라는 한 문장이 전부 | 동일 |
| 층당 표본 수 | 초기 12점(코드) / 8점(본문) + 이후 ~40% | 초기 8점(코드) / 12점(본문) + 이후 ~60% |
| 층 간 비용비 | **5 : 1** (주), **20 : 1** (보조) — **둘 다 가정값** | |
| 물리적 대응(저자 주장, §3.4.4) | *"CALPHAD 예측 또는 고속 DFT"* | *"정밀 dilatometry, 열분석"* |
| 실제로 그렇게 했나 | **아니다.** CALPHAD 도 DFT 도 dilatometry 도 이 연구에서 실행되지 않았다 | |

**⇒ "층 정의의 근거가 있나, 아니면 있는 데이터가 그래서인가" 의 답: 후자보다 나쁘다.**
있는 데이터가 두 층이었던 게 아니라, **하나뿐인 데이터에서 두 번째 층을 인공적으로 합성했다.** 비용비 5:1 도 측정값이 아니라 *"typical"* 이라는 형용사로 정당화된다. **우리가 이 층 설계를 흉내 낼 이유는 전혀 없다.**

### 12.2 ★2 — 층 간 상관을 어떻게 모형화했나 / 오도(誤導) 탐지

- **모형**: **Multi-Task GP (BoTorch `MultiTaskGP`, task_feature=−1)** — 분리형 커널 `k((x,t),(x',t')) = k_base(x,x') × B_{t,t'}`. 이것은 **ICM (Intrinsic Coregionalization Model)** 이다.
  - ⛔ **Kennedy–O'Hagan 자기회귀형(AR1: y_hi = ρ·y_lo + δ)이 아니다.** 논문은 KO 를 언급조차 안 한다.
  - ⛔ deep MF / co-kriging 도 아니다. §2.5.1 에서 대안(cascade GPR, feature-augmented GPR)을 **한 문단 언급하고 안 쓴 이유를 "원리적 불확실도 전파와 양방향 정보 흐름"** 이라고만 밝힌다 — 실험 비교는 없다.
  - ⚠ 코드는 `MultiTaskGP` 생성 후 `covar_module` 을 **Matérn 5/2 ARD 로 덮어쓴다**(`MFAL.py:297-300`). `task_covar_module`(=B) 은 그대로 남으므로 ICM 구조는 유지된다.
- **B 의 학습된 값**: ⛔ **보고되지 않는다.**
- **오도 탐지 장치**: ⛔ **없다.** 다음 중 어느 것도 하지 않는다 — 층 간 잔차 진단, LF 예측의 순위상관 추적, LF 로 걸러낸 후보의 HF 재확인, LF 신뢰구간 붕괴 경보.
- **가장 가까운 것**: §3.4.4 의 *"Fe-rich(>60% Fe) 영역에서 계산-실험 상관이 Co-dominated 영역보다 높다"* — **수치·그림·코드 전부 없는 서술 한 줄.**
- ⇒ **답: 안 봤다.** 그리고 §10.11 때문에 **이 벤치마크에서는 볼 수도 없었다** — 두 층이 같은 데이터에서 나와 상관이 설계상 보장된다.

### 12.3 ★3 — 획득함수와 층 선택을 동시에 정하는가

| 질문 | 논문의 서술 | **코드의 실제** |
|---|---|---|
| 점 선택 | `α = w_EI·EI + w_KG·KG + w_LCB·LCB`, 단계별 가중치 | 동일 (부호만 `−lcb`) ✅ |

| **층 선택** | *"비용가중 획득함수로 (x,t) 를 선택"* | ⛔ **확률 스케줄 `p_HF = 0.7 − 0.4·progress` 로 뽑는다**(§10.1) |

| 예산 관리 | `total_budget = 0.8·C_high·(n_iter−n_samp)` = 720. `budget_ratio < 0.05` 면 LF 강제 | 동일 ✅ (다만 720 은 여유가 커서 거의 발동 안 함) |

## 13. §우리 cascade 재설계에 주는 것 — **"우리 깔때기의 층을 무엇으로 정의할 것인가"** 구체안 초안

> 근거는 **★1(층 정의)** · **★4(이득 분해)** · **★6(Basu 대조)** 셋뿐이다.
> 논문에 없는 것은 아래에서 **"논문에 없다"** 로 명시했다.

### 13.1 먼저 — 이 논문이 우리에게 **금지하는 것** 3개

1. ⛔ **층 비율을 손으로 정하고 그것을 결과로 보고하지 않는다.** (§10.1) 우리 캐스케이드가 "T2 에서 80% 를 UMA 로 처리했다" 고 쓰려면, 그 80% 가 **결정 규칙의 산물** 이어야 한다. 스케줄이면 스케줄이라고 쓴다.
2. ⛔ **싼 층의 비용을 0 으로 세지 않는다.** (§10.7) 절감은 **GPU-h 로 적분**해서 보고한다.
3. ⛔ **"동등한 품질" 을 서술로 때우지 않는다.** (§10.5) 층을 섞은 쪽의 **최종 판정량과 그 산포**를 반드시 숫자로 낸다.

### 13.2 우리가 실제로 가진 층 — 그리고 각 층이 **무엇을 판정할 수 있나**

우리 후보 층은 (UMA 단일점 → UMA 어닐/이완 → UMA Γ-진동 → DFT SCF → DFT nscf 갭) 이다.
**이 논문에서 배운 판정 기준 하나**: *"그 층의 예측 분포가 **목표 영역** 을 해상하는가"* (§12.5, `Fig. S7`).
그 기준으로 층을 배치하면:

| 층 | 비용(우리) | **무엇을 잴 수 있나** | **게이트로 쓸 수 있나** | 근거 |
|---|---|---|---|---|
| **L0 UMA 단일점** | 초 단위 | 힘·에너지. **구조 붕괴 여부** | 🟠 **"명백한 실패" 만.** 순위 게이트로는 부적격 — 단일점 에너지가 우리 판정량(D_rel, 산화 onset)과 직결되지 않는다 | — |
| **L1 UMA 어닐/이완** | 분 단위 | 완화 구조. **기하 왜곡·자리 선호** | ✅ **구조 게이트로 적합** — Basu 의 Tier 3(완화)이 잡은 것이 여기 대응 | Basu B-2 |
| **L2 UMA Γ-진동** | 분–시간 | **허수 모드** = 동역학 불안정 | ✅ **탈락 게이트로 적합.** 이미 우리 보고량 카드 G4 에 있다(`ndo_…estimand` G4: 음향 3개 외 허수 모드면 `SOFT`, 진행 중단) | 우리 카드 |
| **L2′ UMA-MD → D_rel(600 K)** | 시간 단위 | **이온전도 순위** | ⚠ **조건부.** 비준된 보고량(`D-2026-09-08-cascade-d-rel-estimand`)이지만, **게이트로 쓰기 전에 §13.3 의 사전시험을 통과해야 한다** | 이 논문 §12.5 |
| **L3 DFT SCF** | 시간–일 | 총에너지 차, 힘, **grand-potential 창** | ✅ 판정층 | our_dft_baseline |
| **L4 DFT nscf 갭** | 추가 시간 | **fixed-occ VBM/CBM 고유값** | 🟠 **게이트 아님, 보고량이다.** PBE 과소평가 + 무질서 민감이라 절대값 비교 금지 | CLAUDE.md |

### 13.3 ★ 이 논문이 새로 주는 단 하나의 절차 — **"꼬리 해상도 사전시험"**

> `Fig. S7` 이 가르친 것: **R² 0.55 짜리 대리모델이 목표 구간에서는 완전히 눈이 멀 수 있다.**
> R² 하나로는 안 보이고, **parity plot 의 목표쪽 꼬리** 에서만 보인다.

**절차 (게이트를 켜기 전에 한 번, GPU 소량):**
1. 우리가 이미 **DFT 로 판정한 후보 N개**(작아도 된다 — 10~20)를 고른다.
2. 같은 후보를 **싼 층(L1/L2′)** 으로 잰다.
3. **parity plot 을 그리되 R² 를 보지 말고**, 다음 두 가지만 본다:
   - **(a) 해상도**: 싼 층의 예측값이 **목표 영역(우리 문턱 근방)까지 실제로 내려/올라가는가.** `Fig. S7` 처럼 싼 층이 그 구간에 값을 아예 안 만들면 **게이트로 쓰면 안 된다.**
   - **(b) 순위 보존**: 목표 영역 상위 K 안에서 **Spearman ρ**. (⚠ 전체 ρ 가 아니라 **상위 K 안에서**. Basu 의 MACE-MP-0 ρ≈0 사례와 이 논문의 GPR σ ρ=−0.072 사례가 둘 다 "전체 ρ" 였다.)
4. **(a) 실패 → 그 층은 게이트가 아니라 주석(annotation)** 으로 격하하고 그렇게 부른다.
   **(b) 실패 → 순위용으로도 못 쓴다.**
5. 이 시험 결과를 **결과 보기 전에** 문턱과 함께 `estimand_card.md` §4 에 적는다.

⚠ **이 절차는 두 논문 어느 쪽에도 없다.** Aqib 은 우연히 게이트를 안 만들어 피했고(§12.5), Basu 는 게이트가 없어서 문제를 못 만났다(그 digest §10.3 은 "오차 > 마진인데 썼다" 로 비판한다). **우리가 새로 넣는 것이다.**

| **(a) 배분 규칙의 몫** | 같은 층 비율을 **무작위로** 배분한 대조군과 비교 |
| **(b) 싼 층을 쓴 것의 몫** | 전부 비싼 층으로 돌린 대조군과 비교 |

⚠ **(a) 대조군은 두 논문 어느 쪽에도 없다.** Aqib 은 (b)만, Basu 는 (b)+random 만 한다. **(a) 가 없으면 "똑똑한 배분" 과 "싼 걸 많이 씀" 이 분리되지 않는다** — 이 논문이 정확히 그 함정에 빠졌다.

### 13.6 ⚠ 우리 규모에 대한 정직한 단서

- 이 논문의 설계공간은 **717점**이고 **무작위로 432회면 최적을 찾는다**(`Fig. S6`, figure-read).
- **우리 도펀트 풀은 47 / 89 / 273 종으로 더 작다.**
- ⇒ **전수(exhaustive)를 대조군에서 빼면 안 된다.** 우리 규모에서 AL 기계장치가 이기는지는 **가정할 것이 아니라 재야 할 것**이다. 이 논문도 Basu 도 전수를 대조군으로 넣지 않았다.
- ⇒ 우리가 AL 을 쓸 정당한 이유가 남는다면 그것은 **"평가가 비싸서" 가 아니라 "평가 비용이 후보마다 10–100배 다르고 실패할 수 있어서"** 다. **그 문제는 두 논문 어느 쪽도 다루지 않는다** (Basu 의 Ni 타임아웃이 유일한 근접 사례이고, 그것도 감사 없이 지나간다).

## 14. 기법 용어 미니사전

| 용어 | 뜻 | 이 논문에서 |
|---|---|---|
| **Fidelity (정확도 층)** | 같은 물리량을 서로 다른 비용·정확도로 재는 방법 | 2층: 데이터셋 라벨(HF) vs 30% 학습 GP 예측(LF) |
| **Multi-Task GP / ICM** | 여러 과제(=층)를 하나의 GP 로. 커널이 `k_x(x,x') × B_{t,t'}` 로 **분리**되고 `B` 가 층 간 상관 | BoTorch `MultiTaskGP`, `task_feature=−1`. **B 값 미보고** |
| **Kennedy–O'Hagan (AR1)** | `y_hi(x) = ρ·y_lo(x) + δ(x)` 형 자기회귀 다중충실도 | ⛔ **안 씀. 언급도 없음** |
| **co-kriging** | KO 계열의 다중충실도 크리깅 | ⛔ 안 씀 |
| **EI (Expected Improvement)** | 현재 최고를 얼마나 넘어설 것으로 기대되나 | 식 (7). 탐색 지향(61%) |
| **LCB (Lower Confidence Bound)** | `μ − βσ`. 최소화에서 낙관적 하한 | 식 (8). 적응형 β(식 9–10). 활용 지향(37%) |
| **KG (Knowledge Gradient)** | 이 점을 보면 **최적해의 품질**이 얼마나 좋아지나 (EI 는 관측 최고치 기준) | 식 (11–12) |
| **Simple regret** | `f(찾은 최고) − f(진짜 최적)`. 낮을수록 좋다 | 식 (S6). 후향 오라클에서만 계산 가능 |
| **Cumulative regret** | 매 반복 regret 의 합. "헛수고의 총량" | 식 (S7). GPR-LCB 81.38 최저 |
| **CMA-ES** | 공분산행렬 적응 진화전략. 무도함수 전역최적화 | 대조군. 100런 × 200 iter |
| **Calibration (불확실도 보정)** | 예측 σ 가 실제 오차 규모와 맞나 | `Fig. S8`. **GPR ρ=−0.072 (안 맞음)** vs RFR 0.673 |
| **Coverage gap** | 명목 신뢰수준 vs 실제 포함률의 차 | GPR ≈7.1 · RFR ≈3.6 (figure-read) |
| **VIF (분산팽창인자)** | 다중공선성 지표. `1/(1−R²_j)`, 10 초과면 문제 | PCA 후 1.0 |
| **RFE** | 재귀적 특징 제거 | RF 를 기저추정기로 |
| **Invar** | Fe64Ni36 근방의 초저열팽창 합금 | 세 방법이 전부 여기로 수렴 |
| **CTE** | 선열팽창계수, ×10⁻⁶ K⁻¹ | 목표물성 |
| **후향 오라클(retrospective oracle)** | 정답을 이미 아는 데이터셋 위에서 탐색 알고리즘을 채점 | 이 논문 전부가 여기 해당 |
| **fidelity leakage** | 싼 층이 비싼 층의 정답에서 파생돼 상관이 인위적으로 보장되는 것 | §10.11 — 이 논문의 구조적 성격 |
