## 1. 재현 기록 — **전부 우리 오류**

### 1-1. P0-1 대표 구조 — 비준 카드와 BJ2 가 다른 정책이다 ✅ 재현

| 어디 | 대표 선택 정책 |
|---|---|
| `D-2026-09-08-cascade-d-rel-estimand` (**decision_state: active**) | *"설계의 대표는 **점수 중앙값을 낸 실제 행 하나** … 짝수 복제본이면 좌표 sha256 사전순 앞"* |
| BJ2 제3부 S2 (요청문 267행) | *"배열 간 **최저**를 대표로 — '검색한 배열 중' 으로만 서술"* |

**서로 다른 정책인데 BJ2 가 같은 카드를 active 로 인용했다.** 승계 불가라는 지적이 맞다.
같은 카드의 판정 규칙(*"ρ̂ + Fisher 95% CI + 유효 표본수"*)도 회신 말대로
**예측 점수와 D 의 관계**에 대한 규칙이지 설계별 수송 개선·순위 규칙이 아니다.

### 1-2. P0-2 부모 자리 — Li 만의 문제가 아니다 ✅ 재현

생성기 순서: `substitute_compound_at_sites()` 가 **1단계에서 양이온을 치환한 뒤**
**2단계에서 `find_host_indices_for_site(new, anion_site)`** 를 부른다 — 즉 **이미 바뀐 구조**로
음이온 자리를 나눈다. 그 분류기는 현재 구조의 `sym == 'P'` 로만 판정한다.

modelc 62원자에서 실측:

| | P | S_16e | S_4a |
|---|---:|---:|---:|
| 치환 전 | 5 | 20 | 2 |
| P 1개 → Nd | 4 | **16** | **6** |

원래 PS₄ 코너였던 S **4개**(index 32·37·42·47)가 free S 로 재분류된다.

#### 1-2b. ⛔ 회신이 안 짚은 것 — **P 를 전량 치환하면 두 라벨이 같아진다**

```
p_idx = [i for i, sym in ... if sym == 'P']
if not p_idx:
    return host_idx        # ← 조용한 fail-open
```

P 전량 → Nd 실측: **S_16e 22 · S_4a 22** — 두 자리가 **전체 S 를 똑같이 반환**한다.
Li_24g ≡ Li_48h 와 **같은 병이 음이온 축에서도 재현**되고, 이쪽은 예외도 경고도 없다.
⇒ *"S 는 실제로 구분되므로 괜찮다"* 는 두 가지로 깨진다.

### 1-3. P0-3a 다중 프레임 → IndexError ✅ 재현 (합성 입력)

`contrast_from_forces()` 는 `mask`(1 프레임 길이)로 프레임별 필터 후 `np.concatenate` 하는데,
원소별 루프의 `m2` 는 여전히 **1 프레임 길이**다. `dv` 는 `n_frames × mask.sum()` 행이다.

**ref 와 pred 를 똑같이 준(오차 0) 입력**으로:

| 프레임 | 결과 |
|---|---|
| 1 | 통과 (dF = 0, n_atoms_frame = 5) |
| 2 | ⛔ `IndexError: boolean index ... size of axis is 10 but ... boolean axis is 5` |
| 3 | ⛔ 같은 오류 (15 vs 5) |

### 1-4. P0-3b 서로 다른 실행의 에너지·힘 혼합 ✅ 재현 (합성 입력)

`parse_pw_out()` 는 에너지를 `findall(...)[-1]`(**마지막**), 힘을 `re.search`(**첫 번째**) 로 잡고
`converged`/`job_done` 은 문자열 존재만 본다.

완결 SCF 두 개(A: −100 Ry·F 0.01 / B: −200 Ry·F 0.09)를 이어붙이면:

| 입력 | E (eV) | F[0][0] (eV/Å) | converged | job_done |
|---|---:|---:|---|---|
| A 단독 | −1360.5693 | 0.2571 | True | True |
| B 단독 | −2721.1386 | 2.3140 | True | True |
| **A+B** | **−2721.1386** (=B) | **0.2571** (=A) | **True** | **True** |

**B 의 에너지와 A 의 힘이 한 레코드**로 나오고 플래그는 둘 다 참이다.
회신의 단서(*"실제 회수물이 오염됐다는 뜻은 아니다"*)를 그대로 받는다 — 우리도 회수물
오염은 확인하지 않았다. 다만 **탐지 장치가 없다**는 것이 결함이다.

### 1-5. Q5 Li₂O 는 무도핑 원본이 아니다 ✅ 재현

CSV 실측 `Li2O_*` = **Li24 P4 S19 Cl4 O1** — O 치환이 남아 있다.
BJ 원문 171행의 동일 해시도 `cLi24gaS16e 9191a2977212 == cLi48haS16e 9191a2977212`,
즉 **24g판 ↔ 48h판** 비교이지 host 와의 비교가 아니다. 지적이 맞다.

#### 1-5b. ⛔ 회신이 안 짚은 것 — **7종 중 실제 no-op 은 (화합물·자리) 조합 12개 중 3개뿐**

host = Li24 P4 S20 Cl4 (Li₆PS₅Cl 4 f.u.) 기준 전수:

| 진짜 no-op (host 와 조성 동일) | 치환이 있는 것 |
|---|---|
| `Li2S@S_16e` · `Li2S@S_4a` · `LiCl@Cl_4d` | Li2O@S_16e/S_4a · Li2S@**Cl_4d**(Cl−1,S+1) · LiF@Cl_4d · **LiCl@S_4a**(Cl+1,S−1) · LiBr@Cl_4d/S_4a · LiI@Cl_4d · Li3N@S_16e |

⇒ BJ 의 *"7종은 치환이 no-op"* 은 **화합물 단위 서술 자체가 틀렸다.** no-op 여부는
**(화합물 × 자리) 조합**이 정하고, host 원소끼리의 화학량 변화(Li₂S@Cl_4d, LiCl@S_4a)도 치환이다.
회신은 Li₂O 하나를 짚었는데 **실제 오류 범위는 12 중 9** 다.

> ⚠ 우리 1차 검사도 틀렸었다 — "새 원소가 들어왔나"로 봤더니 Li₂S@Cl_4d 를 no-op 으로
> 오판했다. host 조성과의 차로 다시 세서 고쳤다. 기록으로 남긴다.

### 1-6. Q5 학습 목표에 랭킹이 없다 ✅ 재현

`tools/doping/train_predictor.py` 의 `TARGETS` =
`screen_de_per_atom` · `eos_B0_GPa` · `elastic_E_young_GPa` · `elastic_pugh_GoverB` ·
`migration_volume_fraction` · `sigma_300K_S_cm_NE`.
파일 전체에 `rank`/`ranking` **0건**. *"랭킹을 라벨로 학습한 모델"* 은 확인 사실이 아니다 — 철회한다.

### 1-7. Q1 0 K 열역학이 분율을 준다 ✅ 재현

`tools/doping/ehull_check.py` 가 이미 `pd.get_decomposition(winner_comp)` 의 계수를 받아
`hull_E = Σ e.energy_per_atom × frac` 로 쓰고 `f"{frac:.3f}×{formula}"` 로 출력한다.
*"0 K 는 분율을 안 준다"* 는 정정한다. 회신의 단서도 받는다 — 이건 **조건부 평형 분해 계수**이지
실제 계면의 체적상분율이 아니다.

### 1-8. Q4 음이온 집계 ✅ 재현 — **우리 숫자가 틀렸다**

| | S_4a | S_16e | Cl_4d | 합 |
|---|---:|---:|---:|---:|
| 요청문 167행 | 98 | 74 | 60 | **232** |
| 실측 (237 설계) | **101** | **77** | **59** | **237** |

우리 숫자는 **합이 237 도 안 됐다.** 내부에서 걸렀어야 했다.

### 1-9. Q4 229 ↔ 237 = 8 의 원인 ✅ 재현 — **이번에 닫혔다**

이름에서 `_sNN` + `_x###` 를 모두 지우면 229. 조성 기반은 237. 차이 8 의 출처:

| 이름키 | 담긴 조성 수 |
|---|---:|
| `MgO_chain_Cl_cLi24gaS16e` | 3 |
| `MgO_chain_Cl_cLi24gaS4a` | 3 |
| `ZnO_chain_Cl_cLi24gaS16e` | 3 |
| `ZnO_chain_Cl_cLi24gaS4a` | 3 |

4 × (3−1) = **8**. 정확히 회신 말대로다. `chain_Cl_x200/x400/x600/x800` 이
**실제 Cl 5·6·6·7** 을 담고 있어서, `_x###` 를 일괄 삭제하면 서로 다른 조성이 합쳐진다.
⇒ **229 는 다른 조성을 잘못 합친 수다.** 설계계약 §1 의 *"어느 쪽도 아직 검증 안 했다"* 를
**237 채택 · 229 기각**으로 닫는다.

### 1-10. Q4 concentration 의 분자·분모 ✅ 재현

`substitute_compound.py` 의 `actual_x = n_units / n_fu_actual` — **화합물 unit / host formula unit** 이다.
도펀트 원자분율이 아니다. Li₂O 는 S 20 자리 중 O 1 = **5 %** 인데 열에는 `0.25` 로 적힌다.

### 1-11. Q3 힘 대조 20점의 범위 ✅ 재현

`b2o3_uma_vs_dft_force_prereg_2026_09_08.json` (status **ratified**) 실측:
- 표본 = `{b2o3, modelc} × 시드 {s2, s3} × 700 K × 2–50 ps 창 등간격 5 프레임` = 20 점.
  **독립 설계 20 개가 아니다.**
- 보고량 정의가 **골격 = 비-Li (P·S·B·O·Cl)** → **Li 는 정의상 제외**.
- 카드 §7 이 이미 *"힘 → 동역학 을 잇지 못한다"* 를 적어놨다.

⇒ 회신 말대로 합격 문구는 **"선언한 표본에서 힘 대조 통과"** 까지다. 물리 순위로 승격하지 않는다.

### 1-12. Q7-3 비용 칸 ✅ 재현

`kb/templates/estimand_card.md` 의 표는 **비용 = 견적(계산 전) / GPU-h 실측(계산 후)** 로
두 칸이다. BJ2 제3부의 *"비용은 계산 뒤에 적습니다"* 는 **견적 칸을 통째로 뺀 것**이라
템플릿과 어긋난다. 회신 말대로 *"미지의 탈락수를 요구하지 않는 것"* 과
*"예산 상한 없이 시작하는 것"* 은 다르다.

> *"absolute σ 를 3–5× 과대"* 라고 이미 경고하고 있다.
