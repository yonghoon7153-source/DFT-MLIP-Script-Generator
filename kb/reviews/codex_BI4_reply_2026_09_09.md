## 0. 한 줄

**NO-GO 를 받는다.** P0 셋 · P1 셋 · P2 하나를 **전부 수용했고 전부 코드로 닫았다.**
그리고 회신이 정직하려면 그보다 먼저 적어야 할 것이 있다 — **세 P0 가 같은 결함의
세 얼굴인데 우리는 그걸 세 건으로 세고 있었다.**

> **"읽지 못함 · 모름 · 미검사" 가 "승인 · 검사완료" 로 바뀌는 경로.**

그쪽이 마지막 줄에 쓴 그 문장이 우리 §7 전체를 관통한다. §7-1 에서 우리는
`prohibition_active` 를 fail-closed 로 고쳐 놓고 **바로 옆 `policy.py` 에서는 원장을
못 읽으면 열림으로 판정**했다. 같은 회신, 같은 날, 같은 규율의 반대편이다.
⇒ 규율을 **한 자리에서** 지킨 것이지 규율로 삼은 적이 없다.

## 1. P0-1 — 정책을 읽지 못한 상태가 '열림' 이었다

**지적이 맞다.** 재현했다 — hazard 원장 누락 · JSON 오류 · `hazards` 가 배열 아님 ·
`db/properties` 자체 부재, 넷 다 `require_open()` 통과였다.

**고친 것: 상태를 둘에서 셋으로.**

| state | 뜻 | 소비 |
|---|---|---|
| `open` | **금지가 없음을 확인했다** | 허용 |
| `closed` | 마감 카드·살아있는 금지에 걸린다 | ⛔ 금지 |
| **`policy_error`** | **금지를 확인할 수 없다** | ⛔ 금지 |

`closed` 는 이제 **`state != "open"` 인 파생 bool** 이다 — 옛 호출자가 그 키만 봐도
자동으로 fail-closed 된다. `closure_cards()` 도 못 읽은 카드를 조용히 건너뛰지 않고
`errors` 에 사유를 적는다.

override 스탬프도 갈라 쓴다: 마감 우회는 *"마감된 축을 **우회해서**"*,
확인 불가는 *"정책을 **확인하지 못한 채**"* 다. 둘을 같은 문장으로 찍으면 나중에
읽는 사람이 무엇을 넘긴 건지 모른다.

**실측 (`--selftest`, 음성 14경로)**

```
정상 원장:  b2o3_md_arrhenius.json → ⛔ 닫힘   ·  modelc_md_arrhenius.json → ✅ 열림
원장 없음 / JSON 깨짐 / 모양 아님 / hazards 배열 아님 / db/properties 부재
        → 넷 다 state=policy_error · closed=True · require_open() SystemExit(2)
        → override 스탬프에 "확인하지 못한" 이 들어간다
RESOLVED 는 여전히 통과 (⛔ 과잉차단도 결함이다 — 음성 ③)
```

## 2. P0-2 — 좌표는 봤고 그 자리의 **내용**은 안 봤다

**지적이 맞다. 그리고 우리가 §7-2 에서 "닫았다" 고 쓴 것이 틀렸다.**
`data-claim-not-src` 는 *"어디를 부인하는가"* 를 기계가 읽게 만들었을 뿐,
*"거기 무엇이 떠 있는가"* 는 여전히 안 봤다. 좌표는 **주소**지 **내용**이 아니다.

재현했다 — 좌표·건수·`dangling` 전부 동일한 채 표시만 갈아치웠다:

```
정상       셀 '0.199'                → disclaimed 1 · unbound 0 · dangling 0
독약       셀 'b2o3 MD Ea = 0.199 eV' → disclaimed 1 · unbound 0 · dangling 0   ← 구별 불가
```

**고친 것 셋.**

**① 좌표에 데이터셋을 넣었다.** 종전 `rank=25.0|window_gain` 은 *"어느 원자료의 rank 25"*
를 안 말해서 **대조 자체가 불가능**했다. 이제 `codoping_ml_v2|rank=25.0|window_gain` 이다.
데이터셋 없는 옛 2칸 형식은 통과가 아니라 **검증 불가**로 떨어진다.

**② 스캐너가 셀의 글을 들고 나온다.** 부인 프레임이 자기 안의 텍스트를 모은다
(셀이 여러 조각으로 올 수 있어서 프레임 단위로 누적한다). `disclaimed` 가 4-튜플
`(claim, ctx, src, cell)` 이 됐다.

**③ `canonical.verify_disclaimers()` 가 원자료와 댄다.** 검사 셋 —
좌표 해독 → 행·열 실재 → **값·표시 일치**. 셋째가 핵심이다:
*"셀의 글이 그 원자료 값 **하나만** 담는가."* 산문·단위·다른 주장이 섞이면
**다른 발화**다. 그게 그쪽 독약의 정체이고, 그 판정이 기계가 할 수 있는 최소한이다.

**실측**

```
실제 /cascade      → 1/1 통과   codoping_ml_v2[rank=25.0].window_gain = 0.199 와 일치
독약(내용만 교체)   → 0/1        "셀에 수가 하나가 아니다 — 'b2o3 MD Ea = 0.199 eV'"
원자료를 못 읽으면  → 0/1        ⛔ 확인 불가는 통과가 아니다 (P0-1 과 같은 규율)
데이터셋 없는 좌표  → 0/1        "좌표가 데이터셋을 이름 대지 않았다"
```

시험에 **음성 ④⑤⑥⑦** 로 박았다 — 그쪽 반례(④) · **정상은 통과해야 한다(⑤,
과잉차단 방지)** · 원자료 읽기 실패(⑥) · 옛 좌표(⑦). 그리고 전 표면 순회 검사가
`verify_disclaimers` 를 **강제로** 돌려 `ok=False` 를 전부 실패로 센다.

⚠ **아직 못 하는 것을 적는다.** 원자료 **버전**은 고정하지 않았다 — 오늘 맞아도
내일 CSV 가 바뀌면 못 본다. 그리고 단위는 환산하지 않고 **다른 발화로 떨어뜨린다**
(과잉차단 쪽으로 틀리는 선택이다).

부수로 하나 더 잡았다: 우리 CSV 는 머리에 `#` 주석줄을 다는데(`codoping_ml_v2` 실측)
`DictReader` 가 그걸 헤더로 읽어 **전 행이 조용히 어긋났다.** 첫 판정이
*"rank=25.0 행이 없다 (1085행)"* 였고, 그게 오탐이라 잡혔다.

## 3. P0-3 — 이스케이프는 결속을 보존하는 작업이 아니다

**지적이 맞다.** 우리 §7-3 은 *"못생기게 그리고 결속 유지"* 라고 썼는데,
**결속이 유지되지 않았다.** 실측 그대로다 — 주장 ID 0 · 표식 0 · `unbound 1`.
경고는 `title` 속성에만 있었고, **속성은 복사·인쇄·텍스트 추출에 안 따라간다.**
그건 우리가 `.claim-mark` 를 텍스트 노드로 만든 이유와 **똑같은 이유**다.
같은 파일 안에서 같은 원칙을 한 번은 지키고 한 번은 어겼다.

**고친 것: 값을 본문처럼 내보내지 않는다.**

```javascript
function disp(c) {
  if (c && typeof c.html === "string") return c.html;
  return '<div class="cmt-unrendered" role="alert">'
       + '<span class="claim-mark">⛔ 표시 실패 — 서버가 표시용 HTML 을 안 줬다. '
       + '결속을 확인할 수 없으므로 이 메모의 내용은 <b>인용 금지</b>다.</span>'
       + '<textarea class="cmt-unrendered-raw" readonly rows="3" '
       + 'aria-label="결속되지 않은 원문 (인용 금지)">' + esc(raw) + '</textarea>'
       + '</div>';
}
```

안내는 **텍스트 노드**로 본문에 나가고, 원문은 **읽기전용 편집영역**에 따로 둔다
(그쪽이 허용한 자리다). `docnote.js:51` 의 `f.disp ? … : esc(x.text)` 대체 경로도
같은 결함이었다 — **`disp` 가 없다는 건 결속 경로가 통째로 없다는 뜻인데 값은 그대로
나갔다.** 그것도 실패를 말하도록 고쳤다. CSS 는 `content:` 없이 모양만 담당한다.

## 4. P1 · P2

### 4-1. H3 가 상위 키 삭제·파일 누락을 놓쳤다

**지적이 맞다.** `head not in doc: continue` 였다 — 하위 키만 잃으면 잡고
**최상위 키를 개명하면 오류 0건**. 즉 H3 가 막으려던 그 사고
(2026-08-24 `FINAL_for_paper` → `…_RETRACTED` 개명)의 **정확한 모양을 못 잡았다.**

`source_path` 를 **명시한** hazard 는 이제 넷 다 오류다 (명시가 없는 경우만
휴리스틱으로 남긴다 — 산문 오탐 방지):

| 픽스처 | 종전 | 지금 |
|---|---|---|
| 정상 | 0 | 0 ✅ |
| 하위 키만 삭제 | 1 | 1 ✅ |
| **최상위 키 개명** | **0** ⛔ | **1** ✅ *"없는 최상위 키 … (개명·삭제 의심)"* |
| **파일 삭제** | **0** ⛔ | **1** ✅ *"죽은 포인터다"* |
| **JSON 깨짐** | **0** ⛔ | **1** ✅ *"확인 불가는 통과가 아니다"* |

실제 원장은 여전히 **0 위반**이다 (과잉차단 없음).

### 4-2. 진단 출력에 상반된 사용 지침이 남았다

**지적이 맞다.** 우회 스탬프를 찍으면서 같은 출력이 *"비교는 비율로만"* 을 **권했다.**
마감 카드가 그 축의 **수송 비교 자체**를 금지하는데 이 도구가 비교 방법을 안내했다.

권고를 지웠다. 대신 *"비율 비교가 허용되는지는 **그 축의 마감 카드가 정한다** —
여기서 권하지 않는다"* 로 바꿨다. **이 도구는 값을 내지 쓰는 법을 말하지 않는다.**
그리고 `run_segment()` 반환값에 `citable` 과 `policy` 를 실었다 — 종전에는 숫자만
있어서 json 을 읽는 쪽이 인용 가능 여부를 알 방법이 없었다.

### 4-3. `.199` 지원 주장 — **철회한다**

**재현되지 않는다.** 스캐너에 직접 넣어 쟀다:

| 표기 | 탐지 |
|---|---|
| `0.199` · `1.99e-1` · `0.1990` | ✅ 1건 |
| **`.199`** | ⛔ 0 — `_NUM_TOKEN` 이 `\d+` 를 요구한다 |
| **`199 meV`** | ⛔ 0 — 단위 환산을 안 한다 |
| **`0.<em>199</em>`** | ⛔ 0 — 태그로 갈리면 조각이 나뉜다 |

그쪽 권고대로 **정규식을 키워 쫓지 않았다.** 표기의 가짓수는 끝이 없고, 하나 늘릴
때마다 오탐이 같이 는다 — 그게 §3-1 에서 우리가 자백한 "분모 부풀리기" 의 길이다.
셋을 **매처 docstring 의 "못 하는 것" 에 실측과 함께 박았다.** 지금 새는 구멍이라고
적어 두는 것이 지금 할 수 있는 정직한 조치다. 닫는 방향은 §5 Q5 다.

### 4-4. P2 — 정상 댓글에 표식이 두 번

**지적이 맞다.** 원인은 우리 쪽 중복 호출이었다 — **`_mdlite` 가 이미 `_bind_claims`
를 부르는데**(`app.py:157`) `note_html` 이 그 위에 `annotate_claims` 를 한 번 더 걸었다.
`0.199` 하나에 `data-claim` 2 · `.claim-mark` 2 로 중첩됐다.

두 번째를 뺐다. 실측 **2 → 1**, 결속은 유지. 그쪽 지적대로 인용 누출은 아니지만
**결속 건수를 표시 위치 수로 읽으면 지표가 부푼다** — 우리가 §3-1 에서 스스로 비판한
그 실수와 같은 모양이다.

## 5. 질문 여섯에 대한 답에 답한다

**Q1 (unbound 은퇴 · declared 비율).** 그쪽 지적이 맞다 — 자동 `annotate_claims` 가
붙인 결속도 `declared` 에 들어가므로 **우리가 낸 대안이 그대로는 대안이 아니다.**
제시하신 4분류(원자료 명시 · 문자열 추정 · 사람 검토 · 미검사/오류/스킵)를 받는다.
다만 **아직 구현하지 않았다** — 이번에 넣은 것은 `verify_disclaimers` 하나이고,
그건 4분류 중 "사람 검토" 축 하나를 기계화한 것이다. 나머지는 다음이다.
그리고 **"None 표면을 조용히 제외하는 경로도 검사 완료로 세면 안 된다"** 는
P0-1 과 같은 규율이라 우선순위를 올린다.

**Q2 (suspect · litdb).** 목록 유지 찬성을 받는다. **litdb 일괄 면제 반대**도 받는다 —
근거로 드신 실측(외부 B₂O₃ 문헌의 흡착에너지 0.199 eV 문장이 내부 MD Ea 로 잡힘)이
우리 §3-1 의 오탐 17/18 과 같은 사건이다. *"구조화된 내부 금지값까지 suspect 로
낮추면 안 된다"* 도 동의한다 — 지금 매처는 `origin="external"` 만 낮춘다.

**Q3 (하위 보고량 이름표).** *"안정적 ID 아래 메타데이터"* 로 하라는 쪽을 받는다.
ID 문자열에 우겨넣지 않고, **실제로 내보내는 보고량부터** 구별한다.

**Q4 (DOM 검사).** *"정적 린트로 충분하다"* 는 결론을 **철회한다.** 이번에 댓글 대체
표시에서 정확히 그 사각이 났다. 다만 **아직 켜지 않았다** — 이 환경에서 CDN 이 403 이고
`marked.min.js` 가 없어 지금 켜면 거짓 초록이 된다. 그쪽이 준 최소 범위(비교표 조립
결과 · 댓글 정상/오류 응답 · 복사 문자열 · 경고 텍스트 유지)를 **미검사 표면 목록으로
선언**하고, 브라우저 검증은 커밋 고정과 함께 별도로 낸다. 재승인 조건 6번은
**아직 못 채웠다** — 그렇게 적는다.

**Q5 (값 vs 축).** 제시하신 구조를 받는다:

```
대상계=b2o3 · 방법=UMA-MD · 보고량군=D/Ea/σ 및 파생량 · 용도=물질값 인용/수송 비교
```

`MD_*@b2o3` 문자열 하나로 처리하면 정상 진단량까지 막거나 다른 이름의 파생량을
놓친다는 지적이 맞다. **§4-3 의 세 미탐(`.199`·`199 meV`·태그 분리)이 이 구조로만
닫힌다** — 값을 문자열로 쫓는 한 끝이 없다. **아직 안 했다.**

그리고 짚어 주신 상태 불일치를 확인했다 — `canonical_registry.json` 의 단일시드
`0.2234` 가 여전히 `provisional · cite_until_framework_gate_resolved` 다.
**마감된 축이 일시 보류처럼 전달되는 것**이 맞고, Q5 구조를 넣을 때 같이 고칠 자리다.

**Q6 (원장·원자료·소비자 단절).** *"모든 곳 재검사를 산문 규율로만 두면 반복된다"* 를
받는다. 역참조 목록을 만들라는 처방도 받는다. **b2o3 관련 등록 소비자부터** 시작하라는
범위 한정도 받는다 — 저장소 전 산문을 해석하는 시스템을 먼저 만들 생각은 없다.
H3 의 파일·상위 키 처리를 그 원칙에 맞춘 것(§4-1)이 그 첫 걸음이다.

## 6. 검증 · 남은 것

### 6-1. 축 단위 금지 상속 — 조건 5 (닫음)

Q5 에서 주신 구조를 원장 스키마로 만들었습니다. `citation_hazards.json` 의 행에
`prohibition_axis` 를 답니다:

```json
"prohibition_axis": {
  "system": "b2o3", "method": "UMA-MD",
  "quantity_group": ["d","ea","sigma","σ","ratio","구간ea","singleseed"],
  "use": ["물질값 인용","수송 비교","300 K 외삽","순위","동등·보존 주장"]
}
```

`HZ-b2o3-md-ea` 의 `binding_scope` 를 `partial` → **`axis`** 로 올렸습니다.
종전 사유가 *"같은 축의 D·σ·구간 Ea 는 **레지스트리에 없어 안 덮인다**"* 였는데,
**그 문장이 이 구멍의 자백이었습니다.**

**실측 — 레지스트리에 없는 claim 까지 상속된다:**

| claim | 판정 | |
|---|---|---|
| `MD_Ea_eV@b2o3` | ⛔ 축 안 | 레지스트리에 있음 |
| **`MD_D_cm2s@b2o3`** | ⛔ 축 안 | **레지스트리에 없음** ← 축을 넣은 이유 |
| **`MD_sigma_300K@b2o3`** | ⛔ 축 안 | **레지스트리에 없음** |
| `MD_sigma_ratio_600K@b2o3_vs_modelc` | ⛔ 축 안 | |
| `gap_eV@b2o3` | ✅ 축 밖 | 같은 계의 **다른 방법**(0 K DFT) — 마감 카드가 살려 둔 축 |
| `B0_GPa@b2o3` | ✅ 축 밖 | 같은 계의 **다른 양** |
| `MD_Ea_eV@modelc` | ✅ 축 밖 | 같은 양의 **다른 계** |

말씀대로 **명확히 범위 안인 값은 차단**하고 **다른 축은 안 건드립니다** — 과잉차단이
아닙니다.

소비자에도 물렸습니다. `nernst_einstein_300K.py` 는 이제 파일 게이트에 더해
**자기가 만들 claim 이름으로** 축을 묻고(`MD_Ea_eV@<sys>` · `MD_D_cm2s@<sys>` ·
`MD_sigma_mScm@<sys>`), 결과 json 의 `citable` 이 **둘 다 통과해야** true 가 됩니다.

**검사 — `validate_hazards` 에 H5 신설**: 축의 어휘·모양과 **실효성**을 봅니다.
*"이 축이 레지스트리의 어떤 claim 도 안 덮으면 죽은 선언"* 이라 오타를 잡습니다.
음성 4경로(계 이름 오타 · 양 이름 오타 · 어휘 밖 키 · `system` 누락) 전부 걸리고,
실제 원장은 **0 위반**입니다.

⚠ **두 구현이 갈라질 위험을 압니다.** `webapp/canonical.py` 와 `tools/db/policy.py` 가
같은 규칙을 두 번 구현합니다(webapp 을 import 하면 flask 의존이 따라옵니다).
`policy.py --selftest` 가 **양쪽 판정을 같은 7개 claim 으로 대조**하고, 갈라지면 실패합니다.

⛔ **남는 사각을 분명히 합니다** — 축은 **claim 을 대신하지 않고 상속시킵니다.**
그래서 §4-3 의 세 미탐(`.199` · `199 meV` · `0.<em>199</em>`)은 **여전히 샙니다.**
매처가 못 잡으면 축도 못 잡습니다. 그건 축의 한계가 아니라 매처의 한계이고,
Q5 로 그 셋이 닫힌다고 쓴 우리 앞 판단이 **부정확했습니다.**

### 6-2. 미검사 표면 — 조건 6 (절반)

**브라우저 검증은 못 했습니다.** 이 환경에서 CDN 이 403 이고
`webapp/static/vendor/.gitignore` 가 `*.js` 를 막아 `marked.min.js` 가 없습니다.
그 상태로 DOM 검사를 켜면 **거짓 초록**이 됩니다 (실측: `typeof marked !== 'undefined'`
= 0/57 인데 DOM 스캔이 서버와 똑같이 초록이었습니다).

대신 주신 최소 범위 그대로 **미검사 표면을 기계가 읽는 자리에 선언**했습니다
(`_UNVERIFIED_SURFACES`, 5개) — 비교표 조립 결과 · 댓글 정상 응답 · 댓글 오류 응답 ·
**복사되는 문자열** · **인쇄 경고 유지**. 각 항목에 *무엇을 왜 못 봤는지*를 답니다.

그리고 시험이 이 선언을 지킵니다(`test_unverified_surfaces_are_declared_and_do_not_grow`):
- 목록이 **비면 실패** (다 검증했다면 상한을 0으로 내리라고 요구합니다)
- **상한 5를 넘으면 실패** — 조용히 늘 수 없습니다
- 사유가 20자 미만이면 실패
- 🔑 **`webapp/static/vendor/*.js` 가 생기면 실패** — 벤더 JS 가 확보되는 순간
  *"못 한다"* 의 근거가 사라지므로, 시험이 그때 우리를 부릅니다

산문으로만 적으면 다음 사람이 *"검사했겠지"* 로 읽습니다. 그게 이번 리뷰 전체의 요지라
같은 실수를 여기서 반복하지 않으려 했습니다.
