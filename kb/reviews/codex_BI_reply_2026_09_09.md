## 1. 전면 수용 — 그리고 무엇을 했나

### 1-1. P0-1 원장 3중 모순 (**가장 아팠다**)

지적이 맞다. 그리고 **재현해 보니 더 나빴다**:

- `FINAL_for_paper.Ea_eV_PAPER` 라는 키는 `b2o3_md_arrhenius.json` 에 **존재하지 않는다.**
  실재 키는 `Ea_eV_PAPER_SUPERSEDED_600K_only` 와 `Ea_eV_PAPER_RETRACTED_2026_08_23` 뿐이다.
  **⚠ 이 문장을 정정한다 (초안에는 "3주" 라고 썼다).** git 으로 실제 이력을 뽑으니 더
  나쁜 동시에 더 흥미로운 모양이었다:
  · **2026-08-12** (`8700aa7e4`) hazard 가 *"이 키만 인용하라"* 를 넣었다 — **그때는 그 키가
  실재했다.** 지시는 옳았다.
  · **2026-08-24** (`01e61ee24`) 원자료 쪽에서 그 키를 `…_RETRACTED_2026_08_23` 으로 개명했다.
  **그 순간 hazard 의 포인터가 죽었고, 아무도 안 봤다.**
  · **2026-09-08** 이 리뷰로 발견.
  ⇒ 죽어 있던 기간은 **15일**이고, **오기가 아니라 dangling reference** 다. 즉 "누가 잘못
  적었나" 가 아니라 **"원자료를 고칠 때 그것을 가리키는 원장을 아무도 재검사하지 않는다"** 가
  결함이다. 그래서 고친 것이 문구가 아니라 `validate_hazards()` 의 **H3(점표기 키 실재)** 다.
- `C.validate()` 와 `C.validate_governance()` 가 **둘 다 0 위반**이었다. 원장 셋이 각자
  자기 문법만 검사하고 **서로를 안 봤다.**
- 그리고 `retracted.usable_instead` 가 *"저온 구간만: Ea = 0.2241 ± 0.0606 eV"* 였는데,
  그건 우리 자신의 비준된 마감 카드가 **"0.222 eV 포함" 이라고 못박아 금지한 값**이다.
  즉 **원장이 자기가 금지한 값을 대체값으로 권하고 있었다.**

**근본 원인은 거짓말이 아니라 스키마다.** `validate()` 가 빈 `usable_instead` 를 **거부**했다.
"인용 가능한 수 0개" 를 적을 자리가 없으니 사람이 아무 문장이나 채운 것이다.

**고친 순서 (순서가 중요하다 — 뒤집으면 문구를 고치는 순간 validate 가 빨개진다):**

1. **스키마부터 연다.** `retracted.instead_kind ∈ {sentinel_none, claim_ref, prose}`.
   - `sentinel_none` — `{"none": true, "decision": "D-…", "why": "…"}`.
     **비준된** 결정 id 를 반드시 든다(미비준 결정으로는 대체값을 없앨 수 없다).
   - `claim_ref` — `"<metric>@<system>"`. **대체값 자신이 인용 가능한지까지** 본다
     (철회값을 철회값으로 대체할 수 없다).
   - `prose` — 자유 문장. 검사기가 정당성을 못 본다는 뜻이므로 **사람 서명**
     (`instead_reviewed_by` + `instead_reviewed_at`) 없이는 못 지나간다.
2. **원장을 고친다** — 위 §"집행" 넷. 종전 문장은 `superseded_usable_instead` 로 보존했다.
3. **아무도 안 보던 원장에 검사를 붙인다** — `validate_hazards()` 신설.
   H1 level 어휘 · H2 `claim` 실재 · **H3 점표기 키 실재** · H4 id 중복.
   전수 25행에 돌려서 **딱 1건**이 걸렸다(그 죽은 키). 그 1건을 고쳐 지금 0 이다.

실측: `validate` 0 · `validate_governance` 0 · `validate_hazards` 0.

⚠ **이 검사가 못 하는 것을 같이 적는다.** 원장 셋이 **같은 말로 틀린** 경우는 못 잡는다.
일관성만 본다. 값의 물리적 타당성은 여전히 미검사다.

### 1-3. P0-2b 브라우저 재렌더 — **재렌더 자체를 없앴다**

`concept.html` 의 `#md-src` raw 마크다운 → `marked.parse` → `box.innerHTML` 이 서버가 붙인
`.claim-flag` 를 통째로 덮고 있었다. 파서가 둘이면 판정도 둘이 된다.

우회하지 않고 **원인을 없앴다**: 콜아웃 파싱·수식 보호를 서버 `app.doc_html()` 로 옮기고
브라우저 재렌더를 폐지했다. 브라우저는 이제 **부착만** 한다(KaTeX·mermaid·목차).
`marked.parse` 금지 **정적 린트**(음성 경로 포함)로 회귀를 막는다.

저장소 전체 `innerHTML` **90건**(webapp/templates + static/js 전수 grep) 중 서버 결속을 덮던 것은
`concept.html` **딱 하나**였다 (§2-4 참조).

### 1-4. P0-2a / P0-3 `data-claim-not` 담요

구조 결함으로 수용한다. **독약 주입을 우리도 재현했다** — 부인 subtree 안에 자유텍스트로
철회 인용을 넣어도, 숫자만 넣어도 **시험이 통과했다**. `_DISCLAIMED` 가 `(url, claim_id)` 쌍의
**사유 유무만** 보고 건수도 문맥도 안 봤다.

고친 것 둘:
- `gtable` 에 `not_map={열: claim_id}` — 부인이 표 담요(td 600 · 3800자)에서 **열 단위**
  160칸(칸당 ~4자)으로. 표·행을 덮는 부인은 시험이 거부한다.
- `_DISCLAIMED` 가 `{why, n, where}` 를 요구한다 — **건수가 달라지면 실패**한다.
  독약 주입 두 갈래를 실제로 심어서 잡히는지 시험한다.

⚠ **다만 "지금 거짓말을 하고 있다" 는 아니다.** 그 부인 영역 안의 `0.199` 1건은 실제로
`codoping_ml_v2` 의 `window_gain`(단위 V, rank 25, pairA=B2O3/pairB=Gd2O3)이고 b2o3 MD Ea(eV)와
무관하다 — 사유가 **참**이다. 잡은 것은 *"미래에 거짓말을 해도 안 걸린다"* 는 구조 결함이다.

그리고 우리가 **더 정확히** 잰 것: 원자료 1081행에 같은 글자가 **13칸 더** 있다
(`window_gain` 5 · `uncertainty` 4 · `ad_eps` 1 · `ml_score` 1 …). 지금 `[:40]` 이라 안 보일
뿐이고, 표를 늘리거나 정렬을 바꾸면 하나씩 나온다. 그 사실을 `_DISCLAIMED` 에 적어 뒀다.

### 1-5. `/talk/<slug>` EXEMPT 사유가 사실오류

전면 수용. `app.py:1108` 은 `litdb/talks/<slug>.md` 를 연다(사유는 `kb/seminars` 라고 적혀
있었다). stem 과 1:1 이고 8개 전부 200 이다.

**같은 종류의 거짓 사유를 handoff 에서 한 번 고치고 talk 에서 놓쳤다.** 사람 눈이 사유의
참·거짓을 못 지킨다는 실증이라, 면제 자체를 없애고 **반증 가능한 의무**로 바꿨다:
`DYNAMIC_SYNTHETIC` 은 사유뿐 아니라 **그 라우트를 실제로 GET 하는 시험 이름**을 대야 하고,
시험이 실재하는지·그 시험이 정말 그 라우트를 미는지를 다른 시험이 확인한다.

### 1-6. P0-4 결속 능력 없는 렌더러 · Q3 표식 · Q4 침묵 스킵

- **Q3 (표식)** — `_claim_flag` 가 ⛔ 를 CSS `::after` 로만 넣고 사유를 `title` 에만 실었다.
  텍스트만 뽑으면 *"b2o3 의 MD Ea 는 0.199 eV 다."* — 경고가 사라진 채 철회값만 남는다.
  **표식을 실제 텍스트 노드(`.claim-mark`)로** 바꾸고 CSS 는 모양만 담당하게 했다.
  회귀 시험은 종전 title-only 마크업을 같은 검사기에 넣어 **반드시 실패하는지**까지 본다.
- **P0-4 (결속 능력 없는 렌더러)** — 지적의 요지는 *"결속을 붙일 수 없는 경로로 값이 나간다"*
  였고, 재현해 보니 그 경로에 **결속과 무관한 버그가 셋 더** 있었다. `_mdlite`(서버측 경량
  마크다운)를 뜯어서 같이 고쳤다:
  · ⛔ **`0` 이 사라지고 있었다.** `text or ""` 라 falsy 인 값이 통째로 빈 문자열이 됐다 —
    즉 **측정값 0 이 화면에서 없는 값과 구별되지 않았다.** `"" if text is None else str(escape(text))`
    로 고쳤다. 이건 결속보다 나쁜 축이다(결속은 경고를 놓치는 것이고, 이건 **데이터가 사라진다**).
  · 취소선(`~~`)을 안 그려서 **철회 표기 마크업이 평문으로 나갔다** → `_MDL_STRIKE` 신설.
  · 이탤릭이 `D*(design) / D*(host)` 같은 식을 먹어 치웠다 → 낱말 경계 가드 + **음성 픽스처**.
- **Q3 표식이 복사·인쇄로 안 나가던 것과 같은 부류가 하나 더 있었다** —
  `/composition` 의 **📋 값 복사 버튼**이 철회값을 그대로 클립보드에 넣고 있었다.
  이제 `blocked` 목록을 따로 모아 값 옆에 ⛔ 와 함께 *"대신 쓸 값: 원장에 등록된 대체값이 없다"*
  를 같이 복사한다. (§3-4 의 `/explorer` 인용 버튼과 **같은 실수를 두 화면에서** 한 것이다 —
  하나는 리뷰가 짚었고 하나는 우리가 찾았다.)
- **Q4 (침묵 스킵)** — 수용. 아직 다 안 닫았다(§4).

## 2. 정정 — 재현되지 않은 규모 주장 넷

지적의 **실체는 전부 살아 있다**. 아래는 숫자만 바로잡는 것이고, 이걸 안 적으면 우리가
읽지 않고 베낀 것으로 보인다.

### 2-1. ⛔ **이 정정을 철회한다 — "최소 15건" 이 맞았다**

초안은 *"14건이고 15는 근거가 없다"* 고 적었다. **틀렸다. 그리고 틀린 방식이 나쁘다.**

재리뷰가 분해를 알려 주셨다 — 15 = **concept 14 + composition 1**. 우리가 센 14는
`/concept/<cid>` **한 표면만**의 수였고, 15번째는 **우리가 §2-4 에서 직접 실측해 적어 놓은
`/composition/b2o3` · `MD_Ea_eV@b2o3` · `0.199`** 다.

⇒ **같은 회신 안에서 §2-1 이 "15는 근거가 없다" 고 하는 동안 §2-4 가 그 15번째를 보고하고
있었다.** 두 절을 따로 쓰고 합쳐 읽지 않았다.

이게 이번 리뷰의 요지 ①(*"표본으로 전수를 대표시켰다"*)과 **같은 결함**이라는 점을 적어야
공정하다. 우리는 한 표면(concept)에서 센 수를 전체 수로 놓고 상대 숫자를 정정했다.
**전수를 대표시키지 말라는 지적을 받는 회신 안에서 다시 표본으로 전수를 대표시켰다.**

부수적으로 남는 사실 하나만 유지한다(정정이 아니라 참고): concept 14 중 사람이 보는
**표시 위치**로는 11이다 — 스캐너가 같은 자리의 `+90 meV` 와 `90 meV` 를 두 번 세기 때문이다.
이건 우리 스캐너의 세는 단위 문제이고, 리뷰 숫자와는 무관하다.

### 2-2. "bound 92" — **정정하지 않는다**

초안에서 *"재현값은 95다"* 라고 적었다가 뺐다. 이유를 적는 게 낫겠다.

우리 전수 스캔(388~389 URL — 조성 14 · 개념 13 · **talk 7 + README** · handoff 94 · paper 219 ·
정적 22)에서 92 는 안 나왔다. 그런데 **그걸 정정으로 올리는 것이 부정직하다** — 우리가
곧이어 §3-1 에서 *"그 수 자체가 오탐 17/18 로 부풀어 있었고 걸러내면 68 이다"* 라고 적기
때문이다. **자기가 폐기할 척도 위에서 상대 숫자를 세 자리 고치는 것은 정정이 아니라 소음이다.**

⇒ 92 든 95 든 **의미 없는 수**라는 것이 우리 결론이고, 그것만 적는다.
지적의 실체(*"표본으로 전수를 대표시켰다"*)는 §2-4 에서 전면 수용한다.

### 2-3. 행번호 — `composition.html` **25/47 → 29/49**

`c221ac933` 에서 확인: `:29` 가 `<div class="mv">{{ val }}…`(미결속 타일), `:49` 가
`{{ canonical_meta[key]|claimbind }}`(결속본). **지목한 코드 줄 자체는 정확하다.**

### 2-4. ⛔ **이것도 정정이 아니었다 — 겨눌 대상이 없는 정정이었다**

초안 제목은 *"「펼치면 unbound 가 무더기로 남는다」 → 전수 실측 정확히 1건"* 이었다.
재리뷰 지적대로 **리뷰는 「무더기」라고 쓴 적이 없다.** 우리가 지적을 우리가 반박하기 쉬운
모양으로 바꿔 놓고 그걸 정정이라 불렀다. **철회한다.**

그리고 §2-1 에서 적었듯 이 절의 1건이 바로 **리뷰가 센 15번째**다.
즉 이 절은 리뷰를 정정하는 절이 아니라 **리뷰를 확증하는 절**이었다.

아래는 정정이 아니라 **실측 기록**으로만 남긴다.

전 정의역에서 밟은 서버측 미결속은 **`/composition/b2o3` · `MD_Ea_eV@b2o3` · `0.199` 하나**였다.
handoff 94 전수 unbound 0(bound 19) · talk **7편(+README)** 전수 0 · paper 218~227 전수 0(bound 18).
`md_html` 의 자동 결속이 실제로 작동한다.

⇒ **방법론 지적(표본으로 전수를 대표시켰다)은 전면 수용한다.** 초안이 여기 붙여 둔
*"단 「펼치면 무더기」 는 사실이 아니다"* 는 위와 같은 이유로 삭제했다.

그리고 관련해서 두 지적이 한 항목에서 섞였다: **"handoff 94" 는 재렌더(요지 ②) 근거가 아니라
표본(요지 ①) 문제다.** `/api/paper`·`/api/handoff` 로 들어오는 innerHTML 주입 4곳
(literature.html:327 · cascade.html:1423 · benchmarks.html:510 · log.html:94)은 **서버가
`md_html` 로 그린 HTML 을 넣으므로 결속이 살아 있다**(전수 실측 unbound 0).
*"같은 패턴이 여기저기 있다"* 는 뭉뚱그림은 거절한다 — 전수 grep 90건 중 서버 결속을 덮는 것은
concept.html **하나**였다.

### 2-5. 우리에게 **불리한** 방향의 정정 둘 (같이 적는다)

- **"40행 표"** 는 실제로 헤더 포함 **41행 · 15열 · td 600 · 텍스트노드 605 · 3800자**다.

## 3. 리뷰가 못 짚은 것 — 우리가 먼저 올린다

### 3-1. ⛔ 결속 지표의 **분모가 부풀어 있었다** (오탐 17/18)

litdb 219편 전수 자동결속 bound 18 중 **17이 남의 논문**이었다:
deng2026 H₂O 흡착 −0.199 eV 7건 · deng2026 세미나판 3 · spencer2022 exciton 50–90 meV 3 ·
zhu2020 반응에너지 +0.199 2 · ong2013 E_decomp >90 meV/atom 2. 진성은 fan2026 **1건**뿐.

즉 **"bound 95" 라는 수는 남의 논문 숫자를 우리 주장으로 센 결과**였고,
그 상태로 표면을 넓혔다면 "더 넓게 잘못 세는" 검사가 됐을 것이다.

고친 것 — 매처를 **문자열에서 값으로**:
- ① **부호** — `−0.199` 은 `0.199` 이 아니다.
- ② **단위** — 값 뒤 단위가 정본과 다르면 suspect. ⚠ 단, **모르는 낱말은 "다른 단위" 가
  아니라 "단위가 아니다"**. (`Ea 0.199±0.034 vs 0.197` 의 `vs` 를 단위로 읽어 진성 인용
  한 건을 죽였다가 정정했다.)
- ③ **출처** — `origin="external"`(litdb)에서 우리 계 이름이 문맥 창에 없으면 suspect.
  창은 **태그 경계를 넘는다**(러닝 버퍼 240자) — `**동등**` 같은 강조에서 텍스트 노드가
  잘려 바로 앞 문장의 계 이름을 못 보던 것을 고쳤다.

결과: 오탐 17 → 전부 `suspect`, 진성 1건은 `bound` 유지.
`suspect` 는 **조용한 배제가 아니라 목록**이다 — 버리면 오탐 규칙 자체가 감사 불가가 된다.

### 3-2. ⛔ **숫자경계 회피면** — 자릿수 하나로 결속을 벗어난다

종전 매처는 문자열 일치 + `nxt.isdigit()` 가드였다. 스캐너에 직접 먹여 확인:

```
<td>0.199</td>   → unbound 1
<td>0.1990</td>  → unbound 0     ← 결속을 벗어난다
```

`cascade.html:5` 의 `num()` 이 `'%.3f'` 인데 4자리로 바꾸면 13칸이 원장 0줄로 사라진다.
**그건 고침이 아니라 탐지기 회피다.** 그래서 반대로 갔다 — 숫자는 이제 **값으로** 비교한다
(`0.199 ≡ 0.1990 ≡ .199`). 이 회피면 자체를 회귀 시험으로 못박았다.

### 3-3. ⛔ **폐기된 게이트가 살아있는 결속을 요구하고 있었다**

`HZ-beta-hard-gate` 는 `level = SUPERSEDED` 인데 `hazard_claims()` 가 `RESOLVED` 만 걸렀다.
그래서 **폐기된 β 0.80 하드게이트가 오늘도 결속 3건을 요구**하고 있었다
(`β ≥ 0.80` · `베타 하드게이트` · `β 하드게이트`).

고친 것 — level 어휘를 상수화하고 **두 축을 분리**했다:
- `hazard_ids()` = **결속 어휘**(전수). 해소·폐기된 위험도 화면이 **이력으로 이름 댈 수 있어야**
  하고, 그때 유령 결속으로 터지면 안 된다.
- `hazard_claims()` = **결속 요구**(`RESOLVED`·`SUPERSEDED` 제외).
- 어휘 밖 level 은 **살아있는 금지로 친다**(fail-closed). 조용히 건너뛰면 오타 하나로 금지가 사라진다.

⚠ 이 분리 없이 25행 전수에 id 를 달았으면 `RESOLVED` 2행이 dangling 으로 터졌을 것이다.

### 3-4. ⛔ `/explorer` 에 철회값 **원클릭 인용 복사 버튼**이 살아 있었다

`citeVal('B₂O₃-LPSCl','MD Ea','0.199','eV', …)` — 마감된 축의 값이 **한 번 클릭으로
클립보드에 들어가고 그대로 원고로 간다**. `data-claim` 은 달려 있었다.

**결속은 "이게 그 주장이다" 라고 말할 뿐 복사를 막지 않는다.** 이름 대기와 인용 권하기는
다른 축인데 우리는 하나로 보고 있었다. 철회·비인용 칸을 `.cell-blocked`(값은 보이되 버튼
없음)로 바꾸고, "철회값에 citeVal 이 있으면 실패" + "정상 값 버튼이 다 사라지면 실패"
양방향 시험을 붙였다.

### 3-5. hazard 25행 중 **id 가 있는 건 3행뿐**이었다

`hazard_claims()` 가 `if not hid: continue` 로 나머지 22행을 통째로 건너뛴다.
b2o3 행이 `claim: MD_Ea_eV@b2o3` 를 갖고도 **결속 기계에 아예 안 보였다.**
(전수 id 부여는 진행 중 — 이름은 재사용 금지 영구 식별자라 1저자 승인을 받는다.)

  **오늘 실제로 걸리는 것만** 개별 검사로 넣었다(`validate_hazards` H1–H4 · `instead_kind`).
  격자를 켜면 술어 커버리지 40건·파일조인 오탐 23건이 따라오는데, 그건 **검사가 아니라 노동**이다.

**구조적으로 못 하는 것 (이번에 안 닫혔다)**

- ⛔⛔ **마감의 범위가 스캐너의 어휘보다 넓다 — 이게 이번에 배운 것 중 제일 큰 구멍이다.**
  마감 카드는 *"b2o3 의 **D · Ea · σ · 구간 Ea 중 어느 것도** 물질 값으로 인용 금지"* 라고
  **양의 종류**로 금지한다. 그런데 스캐너는 레지스트리에 등록된 **(metric, system) 쌍**만 안다.
  ⇒ **금지 범위 안에 있지만 어휘에 없는 값은 그냥 걸어 나간다.**
  실측 사례: `/requests` 에 **0.2241**(600→800 구간 Ea)이 떠 있었다. 마감이 *"0.222 eV 포함"*
  이라고 **이름을 대서** 금지한 그 값인데, 그 자릿수 표기가 claim 어휘에 없어서 스캐너가 통과시켰다.
  · 이 **개별 건은 오늘 닫았다** (`data-claim="HZ-b2o3-md-ea"` + `.claim-mark`, 실측 확인).
  · **구멍 자체는 안 닫혔다.** 같은 축의 다른 온도·다른 유효숫자·다른 표기가 나오면 또 샌다.
  · 우리가 생각한 방향은 **claim 을 값이 아니라 축으로 선언**하는 것이다
    (`MD_*@b2o3` 전체를 하나의 금지 축으로). 아직 안 했다 —
    **축 단위 결속이 오탐을 얼마나 만드는지 모르기 때문**이고, 그걸 모르는 채로 켜면
    §3-1 에서 우리가 스스로 비판한 "분모 부풀리기" 를 반복한다.
  · **이 문제를 여쭙는다** — 아래 §5.
- 태그 **속성** 안의 값(`/compare` 의 title 툴팁 `b2o3(0.199±0.034)`)은 서버 스캔도 DOM 층도
  못 본다. 목록화만 한다.
- ⛔ **클라이언트가 조립하는 표는 여전히 사각이다 — 자리를 특정했다.**
  `/compare` 는 `<script>` 안에 `"MD_Ea_eV": {"b2o3": 0.199, …}` 를 통째로 싣고
  `compare.html:111` 의 `document.getElementById('cmp').innerHTML = …` 이 셀을 만든다.
  스캐너는 `<script>` 를 건너뛰므로(설계상 그래야 한다) **서버 스캔에 안 잡히고**, 만들어진 DOM
  셀에는 `data-claim` 이 없다. 재렌더를 없앤 것과는 다른 구멍이다 — 정적 린트는
  *"파서를 둘 두지 마라"* 만 지키고 *"JS 가 값을 그리지 마라"* 는 못 지킨다.
  고칠 방향은 **셀 조립을 서버 파생 claim id 로 바꾸는 것**이고, 아직 안 했다.
- claim id 단위가 `(metric, system)` 이라 **"구간 Ea 600→800" 같은 하위 보고량을 못 가른다.**
  sentinel 로 그 자리는 막았지만 온도·창·프로토콜별 하위 이름표가 없다. **다음 누출은 여기서 난다.**
- 원고 .docx·슬라이드·메일·사람이 눈으로 옮겨 적는 것은 못 막는다.
- 원장 셋이 **같은 말로 틀린** 경우는 못 잡는다(일관성만 본다).
- `binds` 에 엉뚱한 claim 을 적으면 검사는 초록이다 — 결정문 산문 ↔ 배선의 일치는 사람만 안다.
- 이 계획은 **누락**을 막지 **거짓 선언**을 막지 못한다. `_DISCLAIMED`·`DYNAMIC_SYNTHETIC` ·
  `binding_scope` 넷 다 "사유를 적으면 통과" 형태이고, 방어는 상한과 음성시험뿐이다.

## 5. 우리가 묻고 싶은 것

1. **`unbound == 0` 을 지표에서 은퇴시키는 게 맞나.** `md_html` 이 일치 자리를 자동으로 감싸므로
   그 경로를 지나는 화면의 0 은 구조적으로 항상 0 이다. 우리 제안은
   **`bound` 중 화면이 `declared` 로 선언한 비율**을 지표로 삼는 것인데, 그러면 자동 결속이
   "도장" 이 되는 것을 지표가 드러낸다. 더 나은 지표가 있나.
2. **`suspect` 를 목록으로 남기는 게 맞나, 아니면 litdb 를 신뢰경계 밖으로 빼는 게 맞나.**
   단위까지 같은 `E_ads = −0.199 eV` 는 타입으로 영원히 못 가른다. 우리는 목록 유지를 택했다.
3. **하위 보고량 이름표** — `(metric, system)` 아래에 온도·창·프로토콜 축을 넣는 것이
   과잉설계인가, 아니면 다음 누출을 막는 최소한인가.
4. **최종 DOM 층을 안 켜기로 한 판단**이 옳은가. 재렌더가 한 곳뿐이었고 그걸 없앴으므로
   정적 린트로 충분하다고 봤는데, 클라이언트 조립 표(`compare.html` 의 `#cmp`,
   cascade combine-tbl)에 철회 문자열이 들어오는 순간 린트는 아무것도 못 본다.
   ⚠ 이 중 `/compare` 는 **초안 이후 닫았다**(§0-1 ①). 질문 자체는 남는다 — 다음 표에서 또 생긴다.
5. 🔴 **claim 을 값이 아니라 축으로 선언하는 것이 맞나** (§4 첫 항목).
   마감은 *"b2o3 의 D·Ea·σ 중 **어느 것도**"* 라고 **양의 종류**로 금지하는데 스캐너는
   `(metric, system)` 쌍만 안다. 그래서 어휘 밖 표기(`0.2241`)가 걸어 나갔다.
   `MD_*@b2o3` 를 통째로 금지 축으로 선언하면 닫히는데 **오탐이 얼마나 늘지 모른다.**
   우리는 §3-1 에서 스스로 *"분모가 부풀어 있었다"* 를 자백했으므로 모르는 채로 켜기가 두렵다.
   · 축 단위 결속을 켜되 **오탐을 `suspect` 로 받는 것**이 답인가?
   · 아니면 마감 카드 쪽이 **금지 대상을 열거로 바꿔야** 하는가 (그러면 카드가 데이터를 따라다녀야 한다)?
6. **우리가 오늘 찾은 셋(§0-1 ②)이 "P0-1 의 부류" 라는 판정이 맞나.**
   맞다면 *"원장·원자료를 고칠 때 그것을 가리키는 모든 곳을 재검사한다"* 를 어떻게 기계로
   만드는가. 지금 `validate_hazards()` H3 는 **hazard → 원자료** 한 방향만 본다.

## 7. 재리뷰 P0 4/4 — 무엇을 어떻게 닫았나 (실측 첨부)

재리뷰에서 P0 넷을 더 받았다. **넷 다 닫았고, 넷 다 실측을 붙인다.** 그리고 그 과정에서
**우리가 만든 검사 하나가 틀린 해석을 정답으로 얼려 놓았던 것**을 발견해 같이 적는다.

### 7-1. P0-1 — 살아있는 금지를 우리가 껐다 (**넷 중 제일 나쁘다**)

우리는 `HAZARD_INACTIVE = {RESOLVED, SUPERSEDED}` 라고 써 놓고 `binding_scope_why` 에
*"…집행되지 않는다"* 라고 사유까지 달았다. **그런데 그 hazard 자신의 `what` 은
*"β ≥ 0.80 하드게이트 — 판정으로 인용 금지"* 라고 적혀 있다.**
⇒ **규칙(rule)이 폐기된 것과 금지(prohibition)가 풀린 것은 다른 일인데 한 어휘로 묶었다.**
폐기된 규칙이 살아있는 금지를 이고 있는 경우가 정확히 이 경우다.

⛔ **더 나쁜 것: 우리 시험이 그 틀린 해석을 기대값으로 얼려 놓고 초록이었다.**
검사가 있다는 것이 해석이 맞다는 뜻이 아니다.

고친 것 — 두 축을 **분리**하고 **fail-closed** 로:

```python
PROHIBITION_STATES = ("active", "inactive")
_PROHIBITION_OFF_BY_DEFAULT = frozenset(("RESOLVED",))   # 명시 없을 때 꺼지는 유일한 level

def prohibition_active(row):
    raw = row.get("prohibition_state")
    if raw is not None and str(raw).strip():
        return str(raw).strip().lower() != "inactive"     # 어휘 밖 = active
    return str(row.get("level", "")).upper() not in _PROHIBITION_OFF_BY_DEFAULT
```

실측:

| 입력 | 금지 살아있나 | 왜 |
|---|---|---|
| `prohibition_state: "weird"` (어휘 밖) | **True** | fail-closed — 모르는 값에 금지를 풀지 않는다 |
| `prohibition_state: "inactive"` | False | 명시적으로 껐다 |
| `level: SUPERSEDED` (명시 없음) | **True** | 규칙은 폐기, **금지는 유효** |
| `level: RESOLVED` (명시 없음) | False | 해소가 유일한 기본 해제 |

결과: **`hazard_claims` 41 → 44.** 세 건이 되살아났다 — **우리가 껐던 금지 셋**이다.
`HAZARD_INACTIVE` 는 지우지 않고 남기되 **"표시 전용, 집행 아님"** 으로 못박았다.

### 7-2. P0-2 — 부인(`data-claim-not`)이 어느 좌표를 부인하는지 기계가 몰랐다

부인은 셀 단위로 달았는데 **"어느 행의 어느 열을 부인하는가" 가 문자열 어디에도 없었다.**
사람은 표를 보고 알지만 스캐너는 못 본다.

`data-claim-not-src` 를 추가했다 — `"{키열}={값}|{열}"` 꼴의 **기계가 읽는 좌표**다
(실측 예: `rank=25.0|window_gain`). 스캐너의 `_stack` 이 이 좌표를 같이 들고 다니고,
`disclaimed` 결과가 `(claim, ctx, src)` 3튜플로 나온다.

⚠ **이걸 넣으면서 우리 독약주입 시험이 깨졌다** — 시험이 `data-claim-not="…">` 라는
**문자열 모양**에 의존했기 때문이다. 정규식으로 다시 쓰면서, 재리뷰가 준 반례
(*"첫 `data-claim-not` 셀이 다른 행"*)를 **음성 ③ 으로 추가**했다.

### 7-3. P0-3 — 결속 능력이 없는 렌더러가 값을 그리고 있었다

댓글·노트는 브라우저가 마크다운을 그렸다. **브라우저는 레지스트리를 모른다** →
그 경로로 들어온 값에는 결속이 원리적으로 안 붙는다.

⇒ **판정을 서버 한 곳으로 옮겼다.** `note_html()` 이 서버에서 그리고 `annotate_claims` 를
태운 뒤 `html` 필드로 내려보낸다(`/api/comments` GET·POST·PATCH 전부).
클라이언트는 **그리지 않고 받은 것만 붙인다**:

```javascript
function disp(c) {
  if (c && typeof c.html === "string") return c.html;
  return '<span class="cmt-unrendered" title="서버가 표시용 HTML 을 안 줬다 — 결속 없이 그리지 않는다">'
         + esc((c && c.text) || "") + "</span>";
}
```

**서버가 HTML 을 안 주면 마크다운을 포기하고 이스케이프한 원문을 보여 준다.**
"결속 없이 예쁘게 그리기" 보다 "못생기게 그리고 결속 유지" 를 택했다.

### 7-4. P0-4 — **원자료를 고쳐도 하류가 안 닫힌다** (구조적으로 제일 넓다)

우리는 `b2o3_md_arrhenius.json` 의 인용 지위를 고쳤다. 그런데
`tools/modelc_v3/nernst_einstein_300K.py` 에 그 파일을 주면 **정상 종료하면서**
`Ea = 0.2241 eV` 와 300 K 외삽 D·σ 를 다시 만들고 *"비교는 비율로만"* 이라고 권했다.
마감 카드가 그 축의 **수송 비교와 300 K 외삽을 둘 다 금지**하는데도.

원인: 그 도구가 개명된 필드가 아니라 **다른 가지**(`⛔_RETRACTED….multiseed_3x3`)를 키 이름으로
훑기 때문에 원자료 정정의 영향을 안 받았다.
⇒ **원장을 고치는 것만으로는 안 닫힌다. 소비자가 정책을 읽어야 한다.**

`tools/db/policy.py` 를 만들어 **소비 시점 게이트**로 걸었다. 마감 카드(`*closed*.json`)의
`근거_파일` 과 `citation_hazards.json` 을 읽고, 금지 판정은 **§7-1 과 같은 fail-closed 규칙**을
쓴다(두 곳에 같은 규약이 있으면 갈라지므로 규칙을 문서에 명시했다).

실측:

```
$ python3 tools/db/policy.py db/properties/b2o3_md_arrhenius.json
b2o3_md_arrhenius.json → ⛔ 닫힘/금지
   · 마감 카드 db/properties/b2o3_md_closed_retrospective_2026_08_25.json — UMA-MD 전도도 축 전체
   · 인용위험 HZ-b2o3-md-ea (BLOCKED) — 축 전체 마감 (D · Ea · σ · 구간 Ea 전부 인용 불가)

$ python3 tools/db/policy.py db/properties/comp2_md_arrhenius.json
comp2_md_arrhenius.json → ✅ 열려 있음 (금지가 **없음을 확인**)      rc=0

$ python3 tools/db/policy.py db/properties/modelc_md_arrhenius.json   # lint-skip-path: 일부러 없는 파일
modelc_md_arrhenius.json → ⛔ 정책 확인 불가 — **허용이 아니다**      rc=3
```
