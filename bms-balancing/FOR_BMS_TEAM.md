## 0. 먼저 — 이 검토가 무엇을 근거로 하나

**코드를 눈으로 읽고 추측한 것이 아닙니다.** 주신 forward model 을 Python 으로
그대로 옮긴 뒤, **같은 파라미터를 넣어 두 구현이 같은 값을 내는지** MATLAB
쪽에서 직접 대조했습니다 (`dd_eval.m` → Python `verify eval --compare`).

4 조합(상태 × Si 소스 × 반쪽전지 소스) × (중간값 앵커 10 + rmse 16)
= **104 개 값이 파일이 담을 수 있는 자리수 안에서 전부 일치**했습니다.
`c_cell` · `E_PE(0.5)` · `E_NE(0.5, 0.25)` 는 마지막 자리까지 같았습니다.

즉 **아래 지적은 "우리가 코드를 잘못 읽어서" 가 아니라 그 모델 자체에 대한
것**입니다. 조건은 `w_dqdv = 0`(현재 기본 설정)입니다.

**고치지 않은 이유**: 저희 쪽 포팅은 결함까지 **일부러 그대로** 옮겼습니다.
고쳐서 옮기면 "규진팀 코드의 성질" 이 아니라 "저희가 만든 다른 모델의 성질"
을 재게 되기 때문입니다. 그래서 발견은 전부 제안으로만 정리했습니다.

## 1. 먼저 — 이미 잘 하고 계신 것

검토 중에 저희가 **잘못 지적할 뻔한 것**이 하나 있어 먼저 적습니다.

`MultiStart` 에 **데이터에서 뽑은 시작점**을 주고 계십니다:

```matlab
gfit = fit_gamma_si(NE_capacity_norm, NE_voltage_raw, ...);
initial5(5) = gfit.gamma_Si_fit;                    % 그 상태 raw NE 에서 γ 추정
...
[initial_combined, ~] = run(ms_pre, problem_pre, 10);   % pOCV 사전 적합
problem = createOptimProblem(..., 'x0', initial_combined, ...);
[fittedParams, ~] = run(ms, problem, 20);               % 그 결과에서 결합 적합
```

γ 초기값을 반쪽전지 실측에서 뽑고, `combined` 를 2 단계로 나눈 것 — **저희
Python 쪽은 이걸 안 하고 무작위 시작만 씁니다.** 좁은 골짜기를 놓칠 위험은
저희 쪽에 있지 그쪽에 있지 않습니다. 이 항목은 제안 목록에서 뺐습니다.

## 2. P0 — 답 자체를 바꾸는 것 두 가지

### 2-1. dV/dQ 모델에 연쇄법칙 인자 `1/a` 가 빠져 있습니다

`electrode_balancing_blend.m`:

```matlab
E_cell_model  = @(p, x) E_PE((x - p(2)) / p(1)) - E_NE_blend((x - p(4)) / p(3), p(5));
dv_cell_model = @(p, x) dv_PE((x - p(2)) / p(1)) - dv_NE_blend((x - p(4)) / p(3), p(5));
```

`E_cell` 이 전극 좌표를 `x_e = (x − b)/a` 로 바꾸므로, 그 도함수에는 `1/a` 가
따라와야 합니다:

```
dV_cell/dx = dE_PE/dx_PE · (1/a_PE) − dE_NE/dx_NE · (1/a_NE)
```

지금은 `dv_PE(...) − dv_NE(...)` 라서 **두 항이 각각 `a_PE`, `a_NE` 배만큼
어긋난 채로** 실측 dV/dQ 와 비교됩니다. 실측 확인:

- 합성 선형 예에서 `E_cell` 의 유한차분은 0.875 인데 `dv_cell` 은 1.5 를 냅니다.
- 실제 적합값에서 `a` 가 1.0~1.18 이므로 **7~15 % 의 계통 오차**입니다.

**수정안** (한 줄):

```matlab
dv_cell_model = @(p, x) dv_PE((x - p(2)) / p(1)) / p(1) ...
                      - dv_NE_blend((x - p(4)) / p(3), p(5)) / p(3);
```

**주의**: 이건 **목적함수를 바꾸는 수정**이라 `w_dvdq > 0` 인 모든 결과가
달라집니다. 고치실 거면 pristine 부터 전 상태를 다시 돌리고 전후를 비교해
주세요. `plotting == "all"` 의 `dv_cell_fit` 도 같은 수정이 필요합니다.

> 저희 판단으로는 이게 **가장 우선순위 높은 항목**입니다. 다만 고칠지는
> 규진팀이 정할 일이고, 만약 의도적으로 그렇게 두신 이유가 있다면 알려
> 주시면 저희 문서에 그렇게 적겠습니다.

### 2-2. 목적함수 scale 의 난수에 seed 가 없습니다 — 재현이 안 됩니다

```matlab
n_samples = 50;
samples = lb + rand(n_samples, 5) .* (ub - lb);
...
scale_pocv = lower_half_mean_local(pocv_vals) + eps;
```

`rand` 앞에 `rng` 가 없어서 **같은 데이터·같은 설정으로 두 번 돌리면 목적함수
자체가 다릅니다.** 최적화하는 대상이 실행마다 달라지는 셈입니다.

실측: 같은 residual 에서 seed 0 과 1 의 목적함수가 **2.0068 vs 2.0201** 로
다릅니다.

**수정안**:

```matlab
if isfield(fit_params, 'scale_seed'), rng(fit_params.scale_seed, 'twister');
else,                                 rng(0, 'twister'); end
n_samples = 50;
samples = lb + rand(n_samples, 5) .* (ub - lb);
```

그리고 **계산된 scale 세 개(`scale_pocv`/`scale_dvdq`/`scale_dqdv`)를 `result`
구조체에 넣어 저장**해 주세요. 지금은 화면에만 찍히는데, 나중에 결과 파일만
보고는 그 실행이 어떤 목적함수를 썼는지 알 수 없습니다.

## 3. P1 — 답이 언제 못 믿을 값인지 코드가 스스로 말하게

주신 결과 97 행을 세어 보니:

| 관측 | 값 |
|---|---|
| 최적해가 상자 경계에 **정확히** 붙은 행 | **32 / 97 (33 %)** |
| 음수 LAM (전극이 늘어났다는 뜻) | **16 / 97** |

경계에 붙은 해의 그 좌표는 **데이터가 아니라 상자가 정한 값**입니다. 그런데
지금 결과 파일만 봐서는 어느 행이 그런지 알 수 없습니다.

### 3-1. 경계 접촉을 결과에 기록 (실패시키지는 말 것)

```matlab
tolb = 1e-6 * max(1, ub - lb);
at_lb = abs(fittedParams(:) - lb(:)) < tolb(:);
at_ub = abs(fittedParams(:) - ub(:)) < tolb(:);
result.active_bounds   = find(at_lb | at_ub)';
result.inference_status = "ok";
if any(at_lb | at_ub)
    result.inference_status = "bound_limited";
    warning('cycle %d: 경계 접촉 — 해석 제한 (%s)', cycle, ...
            strjoin(string(find(at_lb|at_ub)'), ','));
end
```

**행을 지우거나 실패시키지 마세요.** 지우면 선택 편향이 생깁니다. 경고와
플래그만 남기고 그 행을 쓸지는 읽는 사람이 정하게 하는 편이 낫습니다.

### 3-2. 음수 LAM 도 보존 + 경고

`main_blend_final.m` 트렌드 계산부에서 `LAM_PE`/`LAM_NE` 가 음수면 경고만
남기고 값은 그대로 두시길 권합니다. 음수 LAM 은 버릴 쓰레기가 아니라
**잡음·기준 이동·모델 부적합을 드러내는 진단값**입니다.

### 3-3. `fmincon` 종료 상태 확인

```matlab
[fittedParams, fval, exitflag, output] = run(ms, problem, 20);
result.exitflag = exitflag;
result.output   = output;
if exitflag <= 0
    warning('cycle %d: 최적화가 정상 수렴하지 않았다 (exitflag=%d)', cycle, exitflag);
end
```

> 이건 저희가 저지른 실수이기도 합니다. 저희 Python 쪽이 비정상 종료한 결과를
> 성공한 적합으로 채택하고 있었고, 이번에 고쳤습니다. 24 시작 중 5 개가
> 비정상 종료였습니다.

## 5. 왜 이 기록들이 필요한가 — 저희가 측정한 것

수정 제안의 근거입니다. 조건을 떼고 인용하지 말아 주세요.

### 5-1. Si 문헌 곡선 선택이 답을 크게 움직입니다

`300_0009` · GITT · dQ/dV 제외 · **Si 소스 8 종 전체**:

| | 폭 |
|---|---|
| LAM_NE | **8.93 %p** (Jiang 6.11 % ~ Wetjen 15.04 %) |
| LAM_PE | 3.66 %p |
| LLI | 1.02 %p |

그중 `Baggetto`·`Friedrich` 는 γ 가 하한 0 으로 붕괴합니다 (주석에 적어 두신
그대로였습니다). **`SI_SOURCE` 를 결과와 함께 기록해야 하는 이유**입니다.

### 5-2. γ_Si 와 `a_NE` 가 서로를 대신합니다

γ 를 고정하고 나머지 넷을 재적합하면:

| γ_Si | pOCV RMSE | a_NE | LAM_NE |
|---|---|---|---|
| 0.050 | 9.47 mV | 1.209 | **−3.00 %** |
| 0.150 | 5.59 mV | 1.146 | 2.33 % |
| 0.250 | 8.00 mV | 1.073 | 8.58 % |
| 0.325 | 11.00 mV | 1.021 | **13.00 %** |

γ 가 오르면 `a_NE` 가 정확히 반대로 내려갑니다. 물리적으로 당연합니다 —
**Si 가 많은 음극과 가로로 늘어난 흑연 음극이 풀셀 전압에서 거의 같아 보이기
때문**입니다. 그런데 `LAM_NE` 는 `a_NE` 에서 직접 나오므로, γ 가 흔들리면
LAM_NE 가 그대로 흔들립니다.

Schmitt 2022 는 본문에서 γ_Si 와 α_an 이 "같은 서명을 남긴다" 고 적어 놓고
그것을 재지 않았습니다 (논문에 identifiability · degeneracy · confidence
region 이라는 단어가 없습니다). 위 표가 그 자리의 첫 숫자입니다.

**제안 #8**: γ 프로파일을 결과에 첨부하는 함수를 하나 두시면, 그 상태의
LAM_NE 가 얼마나 잘 정해진 값인지 한눈에 보입니다. 다만 **오차막대가 아니라
민감도 곡선**이라고 적어 주세요 (아래 5-4).

### 5-3. 모델을 고정해도 답의 폭이 있습니다

`300_0009` · GITT · Si=Li · dQ/dV 제외 · 최적 목적함수의 **1 % 안**
(경계에 안 붙은 정상 적합):

| | 범위 | 폭 |
|---|---|---|
| LAM_NE | 6.10 ~ 9.50 % | **3.40 %p** |
| LAM_PE | 4.91 ~ 7.78 % | 2.87 %p |
| LLI | 15.15 ~ 16.24 % | 1.08 %p |

같은 데이터·같은 모델인데 음극 손실이 6.1 % 인지 9.5 % 인지 데이터가
가르지 못합니다. **이 값들도 "적어도 이만큼" 이라는 하한**입니다.

### 5-4. 다만 — 이 폭은 신뢰구간이 아닙니다

목적함수가 likelihood 가 아니라 RMSE 합이라, "1 %" 같은 상대 문턱은 통계적
의미가 없습니다. 같은 곡률의 함수라도 기준값이 0.01 이냐 100 이냐에 따라
1 % 띠의 폭이 100 배 달라집니다. 진짜 오차막대를 말하려면 **반복 측정으로
잡음 크기를 추정**해야 합니다.

지금은 "분석자가 고른 민감도 값" 이라고 부르는 것이 정확합니다.

| 자리 | 위험 |
