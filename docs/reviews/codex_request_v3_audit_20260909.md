## 4. 물리 쪽 — 값을 바꾼 것 하나, **일부러 안 바꾼 것 셋**

### 바꾼 것 — 탄소 앵커 (AUD-02)

`predictor_engine` 이 세 곳에서 **"Bielefeld 2023"** 을 인용했는데 (한 곳은 *"directly
measured"*) **그 논문이 리포에 없다** (있는 것은 2019·2020, 둘 다 이 값의 출처가 못 된다 —
2019 는 *"does NOT compute an effective conductivity sigma"*).  그리고 우리 자신의 실측과 **51배**
어긋났다:

```
docs/data/reisacher2023_percolation.csv  (LPSCl = 우리와 같은 SE, + C65, EIS+DC 실측)
  4 wt% → 1.36 mS/cm   ← 실측 (퍼콜레이션 무릎)
  5 wt% → 102  mS/cm
  코드  →  70  mS/cm  @ 4 wt%      ← 5 wt% 쪽 크기다
```
★ 파급을 재보니 *숫자 셋 교체*가 아니라 **탄소 모델이 두 벌**인 문제였다 —
`grade_engine.whatif_additives()` 가 **같은 논문의 p_c 를 `_CARB_PC_WT = 4.0` 으로 이미 쓰고**
있었다.  **문턱은 그 논문에서, 값은 다른 데서.**
⇒ 앵커를 `grade_engine.REISACHER_C65_SIGMA_E_MSCM` **한 군데**로 모으고 예측기가 읽어 간다.
회귀 하나가 **상수를 커밋된 CSV 와 대조**한다.

### 안 바꾼 것 셋

1. **VGCF 0.4 mS/cm** — Reisacher 매트릭스는 **C65 전용**이라 전이되지 않는다.  미확인 라벨 유지.
2. **σ_ion 배수** (×0.99/×0.97/×0.85) — `grade_engine` 의 `_SION_BLOCK_VGCF = 0.05/wt` 와
   어긋나지만(1 wt% 에서 ×0.99 vs ×0.95) 어느 쪽을 고를지는 **별개 앵커 판단**.
3. ★★ **dead-AM 문턱** — 같은 인용이 `predictor_engine.py:812` 에도 있었다.  연도는
   **Bielefeld 2019** 로 정정했는데 그 논문과 코드가 안 맞는다:
   ```
   코드              문턱 ~25-30 vol% AM (고정)
   Bielefeld 2019 Eq8  p_c = 7.83·ln(d/µm) + 36.67 vol%
                       3 µm → 45.3 · 5 µm → 49.3 · 10 µm → 54.7  (Fig5 전이 41~46 / 52~57)
   ```
   **실제 문턱은 45~58 vol% 이고 입경 의존인데 코드는 25~30 고정** — 약 **20 vol%p** 차.
   이 블록이 `electronic_active_pct`(죽은 AM)를 정하므로 **값은 안 건드리고 문헌 대조만** 달았다.
