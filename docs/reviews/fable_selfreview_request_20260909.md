## 5. 탄소 앵커 — 갈아탄 것과 **일부러 안 갈아탄 것**

### 문제

`webapp/predictor_engine.py` 의 도전재 분기가 세 곳에서 **"Bielefeld 2023"** 을 인용했고
(한 곳은 *"directly measured"* 라고까지), **그 논문이 이 리포에 없다.**  정본 litdb 에 있는 것은
`bielefeld2019_...`(구조모델, **σ 를 아예 안 푼다**) · `bielefeld2020_...`(바인더 연속체 σ) 둘뿐.
그리고 그 값은 **우리 자신의 실측과 51배** 어긋났다.

```
docs/data/reisacher2023_percolation.csv   (Batteries 2023, 9(12), 595, open access)
  전도 매트릭스 = Li6PS5Cl (= 우리와 같은 SE) + C65,  EIS + DC-분극 실측
    C65 4 wt% (CM-4, 퍼콜레이션 무릎) → 1.36 mS/cm     ← 실측
    C65 5 wt% (CM-5, 무릎 바로 위)   → 102   mS/cm
  코드 (옛)                          →  70   mS/cm  @ 4 wt%
```
⇒ 70 은 4 wt% 값이 아니라 **5 wt% 쪽 크기**다.  하필 이 구간이 **두 자릿수가 뛰는 무릎**이라
한 칸 오차가 100배 오차다.

★ 그리고 파급을 재보니 *숫자 셋 교체* 가 아니라 **탄소 모델이 두 벌**인 문제였다 —
`grade_engine.whatif_additives()` 는 **같은 논문의 p_c 를 `_CARB_PC_WT = 4.0` 으로 이미 쓰고**
있었다.  **문턱은 그 논문에서, 값은 다른 데서** 가져온 자기모순.

### 조치

앵커를 **한 군데**로: `grade_engine.REISACHER_C65_SIGMA_E_MSCM` (CSV 실측 그대로).
예측기가 그 객체를 **읽어 간다** (임포트 실패 시 같은 값 fallback, 코드에 보이게).
UI 라벨 셋 교체 + 4 wt% 툴팁에 *"무릎이지 포화가 아니다"*.
회귀 7 검사 — 그 중 하나가 **상수를 커밋된 CSV 와 대조**한다.

### 일부러 안 바꾼 것 셋 — **여기가 리뷰의 핵심이다**

1. **VGCF 0.4 mS/cm** — Reisacher 매트릭스는 **C65 전용**이라 전이되지 않는다.
   다른 탄소를 같은 표로 덮으면 그것이 또 하나의 근거 없는 값이 된다.  미확인 라벨 유지.
2. **σ_ion 배수 (×0.99 / ×0.97 / ×0.85)** — `grade_engine` 의 `_SION_BLOCK_VGCF = 0.05/wt` 와
   어긋난다 (1 wt% 에서 ×0.99 vs ×0.95).  어느 쪽을 고를지는 **별개 앵커 판단**.
3. ★★ **dead-AM 문턱** — 같은 인용이 `predictor_engine.py:812` 에도 있었다.  연도는
   **Bielefeld 2019** 로 정정했는데, 그 논문과 코드가 안 맞는다:
   ```
   코드            문턱 ~25-30 vol% AM (고정)
   Bielefeld 2019 Eq8   p_c = 7.83·ln(d/µm) + 36.67 vol%
                        3 µm → 45.3 · 5 µm → 49.3 · 10 µm → 54.7   (Fig5 전이 41~46 / 52~57)
   ```
   **실제 문턱은 45~58 vol% 이고 입경 의존인데 코드는 25~30 고정** — 약 20 vol%p 차.
   이 블록이 `electronic_active_pct` 를 정하므로 **값은 안 건드리고 문헌 대조만 달았다.**

### ⚠ 내가 의심하는 지점

- **1.36 vs 102 중 무엇을 4 wt% 에 쓰는 것이 옳은가.**  나는 CSV 의 4 wt% 행을 그대로 썼지만,
  UI 옵션이 *"percolation!"* 이라 부르던 의도는 **전자망이 형성된 상태**였을 수 있다 —
  그렇다면 의도한 값은 5 wt%(102)이고 **라벨이 틀린 것**이지 값이 틀린 것이 아니다.
  나는 라벨을 믿고 값을 고쳤다.  반대 해석이 맞는가?
- **dead-AM 을 안 고친 것이 보수적인가 방치인가.**  20 vol%p 차이는 작지 않고, 지금도
  사용자에게 보이는 예측을 정하고 있다.  "저자 판단 소관" 이 도피가 아닌가?
