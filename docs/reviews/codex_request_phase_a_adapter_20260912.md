## 0. 상황 — 왜 이 도구가 갑자기 생겼나

Phase A 6 mAh 캠페인의 `vox 0.15` primary **32팔이 완주**했는데(2026-09-12 10:32),
러너 산출물과 판정기 입력의 **스키마가 애초에 안 맞았다**:

| | |
|---|---|
| 러너가 내는 것 | 웹앱 payload `p2_*.json`, 팔당 **150 MB**, σ_e 가 `mpm_metrics.step3.sigma_e_eff_S_cm` |
| 판정기가 읽는 것 | **평평한** `role`/`vgcf_wt`/`vox`/`origin`/`sigma_e` |

판정기가 러너보다 먼저 쓰여(09-09) 그 사이를 잇는 것이 **없었고**, 32팔을 다 돌리고 나서
`키 없음` 으로 드러났다.  기존 `reduce_arm_payloads.py` 는 **SBE/DBE 2역할 16팔 cohort 전용**
이라 4조성 × 8 origin 을 *origin 중복* 으로 보고 진단 모드에서도 거부한다 (그 거부는 옳다 —
표지 없는 부분 cohort 차단 장치).  ⇒ 별도 도구를 새로 썼다.

**저자 결정 (2026-09-12)**: 남은 **72팔**(`0.20` 32 · `0.25` 32 · QC exact replay 8)을
**등록된 그대로 완주**한다.  예산 조항(*"예산을 줄이면 h=0.15 로 좁히고 거친 격자는 secondary
로 강등"*)은 **발동하지 않는다** — 실측 비용이 25~31 h 뿐이라 발동 조건(예산 부족)이 성립하지
않고, 발동하면 **결과를 본 뒤 판정기의 `PREREG` 상수를 고치는 것**이 된다.

⇒ 그래서 **남은 72팔도 전부 이 어댑터를 통과한다.**  검토가 런보다 먼저 값을 갖는 자리다.

## 1. 왜 내가 스스로 검증하면 안 되는가

- 도구를 **내가 썼고**, 그 selftest(정상 4 + 음성대조 11)도 **내가 썼다**.
- 원장의 `verified_by ≠ owner` 규칙(*"구현자 자신은 검증자가 될 수 없다"*)이 막으려는 자리인데
  지금은 그 규칙 **밖**에 있다.
- 그리고 이건 가상의 걱정이 아니다 — **R9 가 판정기의 `replay_gate` 를 fail-open 으로 잡았다**
  (*"false-green 을 막으려고 만든 도구 자신이 그 결함을 갖고 있었다"*).  같은 부류다.

## 2. 도구가 하는 일 (설계 의도)

```
python3 scripts/phase_a_arms_from_payload.py --dir <payload> --out <팔 JSON>
python3 scripts/phase_a_order_verdict.py --dir <팔 JSON>/arms
```

규율로 못 박은 것:
- **조성·격자·origin 을 파일명에서 읽지 않는다** — `vgcf_wt` ← `additives.VGCF.wt_pct` ·
  `vox` ← `step3.vox_um`(매니페스트와 **일치 요구**) · `origin` ← `manifest.origin_shift_um`
  을 `run_receipt.json` 의 `origins` 배열에서 찾은 **색인**.  파일명은 **교차확인 전용**이고
  어긋나면 거부한다.
- **봉인 축 재확인**: `sigma_ptfe_S_cm == 0` · receipt 의 `fibre_stamp`/`ptfe_stamp`/`bridge_um`.
- **수렴 표지가 하나도 없으면 거부**.  판정기는 `cg_info` 부재를 `0`(수렴)으로 읽으므로
  (`int(a.get('cg_info', 0) or 0)`) 그대로 두면 *"모르는 것"* 이 조용히 초록이 된다.
- **판정은 하지 않는다.**  설계 격자점이 비면 판정기가 거부한다 (지금이 그 상태 — 64칸 공백).

## 3. 내가 적대적으로 봐 달라는 지점 (우선순위 순)

1. ★★ **origin 색인 매핑** — `origin_shift_um` 을 receipt 의 `origins` 배열에서 찾아 번호를
   매긴다.  내 검사는 **소속**만 본다 (그 벡터가 배열에 있는가).  배열 순서가 러너가 실제로
   돈 팔 순서와 다르거나, 격자마다 receipt 가 다른 순서로 적히면 **origin 이 뒤섞일 수 있는가**?
   ⚠ 특히 `0.20`·`0.25` 에서는 반-복셀이 0.10 · 0.125 로 **값 자체가 달라진다**.
2. ★★ **조성 교차확인이 진짜 독립인가** — 매니페스트 `wt_pct` 와 **파일명**을 대조하는데
   둘 다 같은 러너가 쓴다.  한 군데서 틀리면 **같이 틀리는** 구조 아닌가?  독립 축이 있나
   (예: `additives.VGCF.n_objects`, `vol_pct_of_solid`, `dilate_z`)?
3. ★ **수렴 규약이 두 층에서 다르다** — 어댑터는 표지 부재를 **거부**하고 판정기는 **0으로 읽는다**.
   이 비대칭이 맞나, 아니면 판정기 쪽을 fail-closed 로 바꿔야 하나?
   (⚠ 판정기는 R9 검토필이라 내가 함부로 못 고친다.)
4. ★ **음성대조 11개가 실제로 발화하는가** — 각각이 *막으려는 결함을 정말 재현*하는지.
   특히 ⑪(설계 칸 중복)·⑨(origin 부재)·⑤(수렴 표지 부재).
5. **QC 조성이 사전등록에 없다** — §1 은 `QC exact replay × 8 origin @0.15 = 8` 이라고만
   적고 **어느 조성을 복제하는지 안 적었다**.  나는 **생산 조성 3 wt%** (NCM:LPSCl:VGCF =
   70:27:3, 원고 조성)를 제안한다 — 결과와 무관한 근거이고 §1 이 secondary 를 *"생산 조성"* 으로
   부르는 것과 정합한다.  ⚠ 이것이 **빈칸 채우기**인가 아니면 **사전등록 변경**인가?
6. **`add_rng_per_phase` 봉인이 실제로 있는가** — §3 이 *"매니페스트 `add_rng_per_phase` 로
   봉인된다 (규칙 M)"* 라고 적는데, **STEP3 매니페스트 61키에 그 키가 없다**.
   킷 5개 `run_mpm.sh` 에는 `--add-rng-per-phase` 가 **전부 있다**(확인함).  STEP2 산출물이
   그것을 봉인하는지, 아니면 봉인 문장이 실현되지 않은 것인지?

## 4. 부수 질문 — `SELF-19` 의 처방

receipt 만으로는 그것을 답할 수 없었다 (payload 매니페스트를 전수로 읽어 `p2` 32/32 확인,

⚠ 삭제 직전에 읽어서 막았는데, **막은 것은 규율이 아니라 우연한 순서**다.
처방 후보: 부재를 오류로 만들면 기존 디렉터리가 전부 막힌다 ⇒ `None` 이면 payload 매니페스트
에서 읽어 채우고 **출처를 기록**하는 쪽.  조용히 통과시키지 않으면서 반입도 막지 않는 형태가
이것이 맞나?
